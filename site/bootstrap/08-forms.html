网页若只会说、不会听，就成了自说自话。表单，是网页与访客对话的窗口： 访客递上名号与口令，页面据此应答。这一式，我们修炼听人说话的功夫。

本式要点
  • form-label 与 form-control 的基本搭档
  • 会用 select 与 checkbox/radio 写选择类控件
  • 用 input-group 给输入框加前后缀
  • 搞清 needs-validation、was-validated 与 novalidate 的分工
  • 认识 form-floating、控件尺寸、form-control-color、form-range 与 is-valid / is-invalid

表单控件的基本搭档

Bootstrap 表单的头号搭档：标签用 form-label， 输入框用 form-control——宽度铺满、圆角、聚焦时亮一圈光晕。 placeholder 是框内的占位提示，但不能替代 label： 输入一开始它就消失，读屏器对它的朗读也并不可靠。辅助说明文字放 form-text 里， 紧跟在控件下面，像一行小字批注。

两个原生属性也常上场：

  • disabled——禁用：灰掉、不能聚焦、提交时整个字段被忽略；
  • readonly——只读：外观不变、可以聚焦复制，提交时值照常送出。

一句话区分：disabled 是“锁在门外”，readonly 是“只许看不许改”。

输入组与登录表单

input-group 能把输入框和它的“前后缀”粘成一条：用 input-group-text 装图标或文字，放在控件之前是前缀，之后是后缀。 下面这个登录表单就用它挂了图标，并且演示了完整的校验反馈——先看效果， 再听分解。

例 1 · 登录表单（输入组 + 校验，点“登入”试试）
名号不能为空。
口令至少 6 位。
名号核对无误，欢迎入内！

校验的戏法拆开来看，一共四步：

  1. 挂旗子：表单写 needs-validation 作标记——这个类本身不带样式， 官方示例里用它当脚本钩子（选中“需要校验的表单”）；本演示为了直观，脚本直接按 id 绑定了表单；
  2. 定规则：字段写 required、minlength 等原生校验属性，下面配一条 invalid-feedback 写错误文案（通过的文案用 valid-feedback）；
  3. 按开关：提交时由脚本阻止默认提交，并给表单加上 was-validated——这个类一出现，红框与错误文案才亮出来；
  4. 留后门：novalidate 关掉浏览器自带的报错气泡，让报错样式统一交给 Bootstrap，全场一个画风。

也就是说：真正把红框与错误文案亮出来的是 was-validated，needs-validation 只是命名约定。要用它当钩子，把脚本里的选择器写成 $('.needs-validation') 即可。

背后的原理很朴素：Bootstrap 用 :invalid/:valid 伪类给控件上色， was-validated 只是决定这些样式“何时可见”，而 checkValidity() 是浏览器原生的体检报告——它照常工作，不受 novalidate 影响。另外注意：invalid-feedback 放进 input-group 时，输入组要补一个 has-validation，反馈文字才知道站哪儿。

下拉、单选与复选

选择类控件各有专属类名：下拉框用 form-select（不是 form-control）； 单选与复选是 form-check 包着 form-check-input 和 form-check-label。同一组单选给相同的 name，浏览器自会互斥； form-switch 则把复选变成拨杆开关。

例 2 · 选择类控件一览
下拉框用 form-select，不用 form-control。

记一个心法：form-check-input 与 form-check-label 靠 for/id 配对——点文字也能选中，手指粗的访客会感谢你。

栅格化表单

第二式的栅格可以直接用在表单上：把 form 写成 row + g-3（竖向留白），字段用 col-md-6 等 列类分配宽度。手机上一列到底，中屏起两列并排——响应式是白捡的。

例 3 · 栅格化报名表单
名号不能为空。
飞鸽地址格式不对。
口令至少 6 位。
口令至少 6 位。
需先同意门规。
名帖已收下，静候佳音！

注意一个细节：整个表单用了同一套校验写法——col-12 里的复选框也带 required，浏览器对复选、单选、下拉的校验一视同仁。至于 DOJO.ready，那是本站加载器提供的“等全部资源就绪再动手”的队列 （第一式提过那个小加载器）；在你自己的页面里，把脚本放在 </body> 之前即可。

表单补遗：浮动标签、尺寸、颜色与即时校验

表单控件还有几样好用的“配件”，一并补齐：

成员用途
form-floating浮动标签：label 平时“住”在输入框里，聚焦或已有内容时浮到框顶——省一行高度
form-control-sm / -lg输入框的小号 / 大号变体（下拉框用 form-select-sm）
form-control-plaintext只读的“纯文本”样式：像正文一样显示，去掉输入框的外观
form-control-color把取色器修成标准尺寸的小方框（配 <input type="color">）
form-range滑块控件（配 <input type="range">）
is-valid / is-invalid手动给单个控件判“合格 / 不合格”，配合 valid-feedback / invalid-feedback 显示反馈
浮动标签的结构要点

form-floating 里，input 必须写在 label 前面，并且 input 上要有 placeholder（哪怕是空字符串）——浮动的动画靠它触发。顺序写反，标签就不浮了。

练功 · 第八式
  1. 把例 1 里口令的 minlength 从 6 改成 8，并同步修改 invalid-feedback 的文案，再点“登入”试试。
  2. 新写一张“拜师申请”表单：输入组前缀挂“@”，栅格三列（姓名 / 籍贯 / 门派，各 col-md-4），底部一个“同意门规”的 form-check。
  3. 思考题：既然要用脚本阻止默认提交并手动加 was-validated，为什么还要给表单加 novalidate？两者不矛盾吗？
参考答案 1

minlength 是浏览器原生校验属性，checkValidity() 认它； 但浏览器不会自动读懂你的中文文案——文案要自己改，否则规则与提示会“各说各话”。 校验的精髓就在这：规则与反馈必须同步。

参考答案 2

栅格只管“分列”，col-md-4 三列刚好平分一行；前缀“@”是 input-group-text，与输入框无缝拼接。两类组件互不干扰，这就是 Bootstrap 组件化的好处。

参考答案 3

不矛盾，因为两者管的是不同的两件事。novalidate 只关掉浏览器 自带的报错气泡，而 checkValidity()、:invalid 这些 校验机制本身照常工作。若不加 novalidate，提交时浏览器会先弹出自己的气泡、 有的字段又有 Bootstrap 红框，两种画风同台，访客眼花缭乱。加了它，报错样式就统一由 Bootstrap 说了算——脚本仍然如实体检，只是把“怎么呈现”的决定权收了回来。

本式小结

  • form-label + form-control 是标签与输入框的标准搭档，form-text 放辅助说明；
  • input-group/input-group-text 拼接前后缀，form-select 与 form-check 各管各的选择控件；
  • row g-3 + col-* 直接栅格化表单，移动端自动堆叠；
  • 校验要点：required 定规则、脚本加 was-validated 亮样式、novalidate 统一画风（needs-validation 只是命名约定，方便脚本找表单）；
  • 配件速览：form-floating（input 在前、带 placeholder）、form-control-sm/lg、form-control-color、form-range；is-valid / is-invalid 可单独判定某个控件。
