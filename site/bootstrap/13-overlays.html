跳到正文

前几式的组件大多“写上属性即生效”。本式三位主角却有些脾气：悬浮提示、弹出说明、角落通知， 都要你亲手写一行 JavaScript 唤醒。这也是本回第一次由你 new 一个 Bootstrap 组件。

本式要点
  • tooltip：data-bs-toggle="tooltip" + title 属性， 必须手动 new bootstrap.Tooltip(元素) 初始化
  • 理解为什么 tooltip / popover 要手动初始化（官方“按需开启”的设计）
  • popover：data-bs-content 装正文，new bootstrap.Popover(元素) 初始化
  • toast：new bootstrap.Toast(元素).show() 弹出右下角轻通知

为什么这几位要“手动唤醒”

Bootstrap 的数据 API 能自动初始化大多数组件——modal、dropdown、collapse、carousel 都是 “写属性即生效”。唯独 tooltip（悬浮提示）与 popover（弹出说明） 被官方刻意设计成“opt-in”（按需开启）：只写属性不写 JS，它们绝不会出现。

官方这么做的理由很实在：

  • 开销：每个 tooltip 都要绑定悬浮、聚焦等一串事件监听。页面上一旦有成百上千个 （比如表格里每格一个），自动全扫就是白白浪费性能；
  • 定位：它们的浮层要用 Popper 定位库计算位置，这也是一笔只在需要时才值得付的开销；
  • 非必需：tooltip / popover 只是锦上添花，就算忘了初始化，也不该影响页面主功能。 所以官方把“要不要开”的决定权交给你。

于是它们的正确用法是“属性 + 一行初始化”，缺一不可：

心法：DOJO.ready——本站的“全资源就绪”队列

在本站页面里写这行初始化，必须包在 DOJO.ready(function(){ … }) 里： 页面上的 Bootstrap 脚本是异步加载的，DOJO.ready 会等样式、脚本全部就位、 页面就绪后才放行你的代码——保证执行时 bootstrap 全局对象一定存在。 正如 $(function(){ … }) 等 jQuery，DOJO.ready 等 Bootstrap 全家桶。

悬浮提示 tooltip

tooltip 是鼠标悬停时冒出的一行小字，用来补充说明按钮、图标的含义。 属性三件套：data-bs-toggle="tooltip" 声明身份、title 提供内容、 data-bs-placement 指定方向——top / right / bottom / left，默认 top。

页面上 tooltip 往往不止一个，所以初始化习惯写成循环：选中所有带 data-bs-toggle="tooltip" 的元素，逐个 new 一遍。

弹出说明 popover

popover 是 tooltip 的加强版：多一个标题栏，还能装正文， 点击触发（tooltip 是悬浮触发）。与 tooltip 相比只多一个 data-bs-content 属性装正文，标题仍由 title 提供。同样需要手动 new bootstrap.Popover(元素)。

默认点一下弹出、再点一下收起。给它加 data-bs-trigger="focus" 更顺手： 点按钮获得焦点即弹出，点页面别处自动收起。

角落通知 toast

toast（轻通知）是屏幕角落一闪而过的小卡片，用来告知“已保存”“新消息到了”， 不打断访客当前的操作。结构分两截：toast-header 放图标、标题、时间与关闭按钮， toast-body 放正文。

它同样是 opt-in：在触发按钮的点击处理里执行 new bootstrap.Toast(元素).show()。 更稳妥的写法是 bootstrap.Toast.getOrCreateInstance(元素).show()—— 同一个元素反复创建实例可能留下“僵尸监听”，getOrCreateInstance 保证有则复用、无则新建。toast 默认约 5 秒后自动消失，可用 data-bs-delay 调整。 真实页面里，整个容器常用 position-fixed 固定在视口右下角。

练功 · 第十三式
  1. 给例 1 再加一个按钮（data-bs-placement="left"，文案写“左方第二枚”）， 并说明为什么初始化脚本一行都不用改（提示：选择器命中了它吗？）。
  2. 把例 2 的 popover 触发方式改成 data-bs-trigger="hover"，观察鼠标移入移出的效果； 再想想：这对手机用户友好吗？
  3. 思考题：为什么 Bootstrap 不给 tooltip / popover 做自动初始化，而 modal / dropdown 却可以 写属性即生效？
参考答案 1

例 1 的初始化脚本用的是 #bs13-demo1 容器内全局选择器，只要新按钮放在 #bs13-demo1 容器里，循环会自动把它也唤醒，一行 JS 都不用改。 这正是用“容器内全局选择器 + 循环”而不是“逐个 getElementById”的好处。

参考答案 2

改成 hover 后，鼠标移入按钮即弹出、移出即收起。但对手机用户不友好—— 触屏没有“悬浮”这回事，点一下往往触发一次 hover 后内容又收起，容易造成困惑。 所以 hover 触发通常只作为桌面端的锦上添花，移动端要有对应的点击方案。

参考答案 3

两点原因：性能与取舍。tooltip / popover 每个实例都要绑定悬浮、聚焦等一串监听， 还要动用 Popper 定位库计算浮层位置；页面里它们常常成群出现（表格里每格一个）， 自动全扫是一笔不小的开销。而 modal、dropdown 这类组件一页最多几个，自动初始化几乎零负担。 同时 tooltip / popover 只是辅助说明，缺了不致命——于是官方把“开不开、开多少”的选择权 交给你：需要时 new 一下，按需付费。

本式小结

  • tooltip 与 popover 是 opt-in 组件：只写 data-bs-* 属性不会生效， 必须手动 new bootstrap.Tooltip(el) / new bootstrap.Popover(el)；
  • 本站演示里初始化一律包在 DOJO.ready(function(){ … }) 里，保证 bootstrap 全局已就位；
  • tooltip 用 title + data-bs-placement 定方向，popover 多一个 data-bs-content，data-bs-trigger 定触发方式；
  • toast 用 bootstrap.Toast.getOrCreateInstance(el).show() 唤醒，默认约 5 秒自动消失。
