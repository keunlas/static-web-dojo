跳到正文

上一式学会了搭架子，这一式要让架子活起来：让列里再装行、让盒子偏一偏、挪一挪、贴紧或散开。 栅格的下半部，全是布局的巧劲。

本式要点
  • 在列里再开 row，实现任意深度的嵌套
  • 用 offset-* 偏移、order-* 排序调整位置
  • 用 align-items-* 与 justify-content-* 对齐行列
  • 用 g-*（gutter 列间距）控制列与列的呼吸距离

嵌套：列中再开一行

栅格可以“套娃”：col 里面还能再放 row，新的一行又是一套完整的 12 列， 与外面互不相干。左侧导航 + 右侧内容区里再分两栏，就是嵌套的典型场景。

例 1 · 外层 4:8，右侧列里再开一行 6:6

嵌套深度不限，但一般不超过两层——每多一层，心算“这行是 12 份里的哪一层”的难度就翻一倍， 可读性也掉一档。

偏移与排序：offset-* 与 order-*

offset-* 让列向右“空出”若干份：offset-md-3 意为 md 起左侧空出 3 份。 居中一个登录框的经典写法就是 col-md-6 offset-md-3——占 6 份、左右各空 3 份，正好居中； offset-0 可以清除之前的偏移。

order-* 只改视觉顺序，不改 HTML 里的先后。经典用法：手机上希望正文先出现 （阅读优先），桌面上希望侧栏在左。HTML 里正文写前面，桌面用 order-md-2 把它挪到右边。

例 3 · order 换序：HTML 里正文在前，桌面上侧栏在左
正文 —— HTML 里排第一；桌面（md 起）被 order-md-2 挪到右侧
侧栏 —— HTML 里排第二；桌面挪到左侧

手机上按 HTML 顺序：正文先、侧栏后；桌面（md 起）按 order 数字从小到大排：侧栏在左、正文在右。 order 取值 1–5，另有 order-first / order-last。

对齐：垂直与水平

行里的列默认被拉伸到与最高的列一样高。在 row 上加 align-items-* 可以统一控制 全部列的垂直对齐：start 顶端、center 居中、end 底端； align-self-* 则加在单个 col 上单独控制。

水平对齐用 justify-content-*：当一行的列宽之和不足 12 份时，多出来的空间怎么分。 取值有六个，含义如下：

取值多余空间怎么分
start全部留在右侧，列从行首排起——这是默认行为；
center左右均分，列整体居中，最常用；
end全部留在左侧，列挤到行尾；
between两端贴边，中间的自由空间均匀分给列与列之间——"一张邮票贴两端"；
around每个列的左右两侧各分到一半自由空间，列与列之间的缝隙是边缘间隙的两倍；
evenly列与列、列与边缘的缝隙全部相等，左右完全对称。

列间距：gutter

列与列之间的间隔叫 gutter（列间距）。默认每列左右各带半份间距，相邻列之间正好 1.5rem。用 g-* 六档（0–5）统一控制：g-* 同时管水平与垂直， gx-* 只管水平、gy-* 只管垂直，数字越大越松、g-0 完全贴死。

参考答案 3

DOM 顺序不变，意味着 Tab 键的焦点顺序、屏幕阅读器的朗读顺序仍是 HTML 里的先后（正文先、侧栏后）， 与桌面上的视觉顺序（侧栏左、正文右）不一致。视觉上在左边的元素，键盘要绕到后面才到，读屏用户 “听”到的页面和“看”到的页面是两回事。所以 order-* 适合重排地位相当的区块 （如本例的正文与侧栏），不适合把表单提交按钮这类关键操作挪到奇怪的位置。

本式小结

  • 嵌套：col 里再开 row，内层是独立的一套 12 列；
  • 偏移 offset-* 空出左份数（居中经典：col-md-6 offset-md-3）；
  • 排序 order-* 只改视觉顺序，不改 DOM 顺序；
  • 垂直对齐 align-items-* / align-self-*，水平对齐 justify-content-*；
  • 列间距 gutter：g-0 到 g-5，gx-* 水平、gy-* 垂直。
