江湖行走，有些话要当面说清——比如“这一页当真要删？”；有些招式要藏进袖中——比如一排备用操作。 本式修炼两件“藏与现”的兵器：模态框与下拉菜单。

本式要点
  • 认识模态框 modal 的完整结构：外层外壳、中层对话框、内层内容三件套
  • 会用 data-bs-toggle="modal" + data-bs-target="#id" 触发模态框，用 data-bs-dismiss="modal" 关闭
  • 掌握 modal-dialog-centered 垂直居中与 modal-dialog-scrollable 框内滚动
  • 会搭下拉菜单：菜单项、分割线、禁用项，以及 dropend 弹出方向
  • 认识模态尺寸类（modal-sm/lg/xl/fullscreen）与下拉附件（dropdown-menu-end、dropdown-header、分割按钮）

模态框：一层盖住页面的对话框

模态框（modal）是一层盖住整个页面的对话框：背景变暗，其余内容暂时不可操作， 逼着访客先处理眼前的事——确认删除、登录、填表单，都是它的经典场景。

它由三层结构组成，缺一层都会散架：

  • modal——最外层外壳，负责盖住页面与变暗的遮罩；
  • modal-dialog——中层对话框，决定宽度与位置；
  • modal-content——内层内容，再分为 modal-header（标题区）、 modal-body（主体区）、modal-footer（按钮区）三部分。

两个触发细节：

  • 打开：按钮上写 data-bs-toggle="modal" 声明身份，data-bs-target="#…" 点名目标；
  • 关闭：元素上写 data-bs-dismiss="modal"，点击即关闭。此外点遮罩、按 Esc 也能关。
心法：data-bs-* 是 Bootstrap 的数据 API

data-bs-* 属性由 Bootstrap 的“数据 API”自动接管——modal、dropdown、collapse、carousel 这些组件只写属性就能生效，一行 JavaScript 都不用写。 不过本回第十三式的 tooltip / popover 是两个例外，先留个悬念，届时见分晓。

例：确认删除弹窗

最典型的模态框场景——点“删除”先弹出确认。这里还加了两道保险： data-bs-backdrop="static" 让点遮罩不关闭，data-bs-keyboard="false" 让按 Esc 也不关闭， 防止手滑造成误删。

垂直居中与框内滚动

默认的 modal-dialog 贴在页面偏上的位置。给它加上 modal-dialog-centered， 对话框便垂直居中，短内容看起来更从容。

如果内容很长（长公告、长条款），再加一个 modal-dialog-scrollable： 滚动条出现在模态框内部，标题与按钮始终可见，而不是把整页顶得看不见头尾。

下拉菜单：把常用招式收进袖中

下拉菜单（dropdown）把一个按钮与一列操作打包：平时只露出按钮，点一下弹出菜单。 结构上是一个 dropdown 容器，里面放着：

  • dropdown-toggle——触发按钮，带 data-bs-toggle="dropdown"；
  • dropdown-menu——菜单本体，条目用 dropdown-item；
  • dropdown-divider——分割线，把条目分组；
  • 禁用条目：加 disabled 类并配 disabled 属性；
  • 弹出方向：默认向下，dropup 向上、dropend 向右、dropstart 向左。

菜单弹出后的位置由 bundle 内置的 Popper 定位库自动计算——空间不够时还会自动翻转方向，不用你操心。

例 3 · 带分割线与禁用项的下拉菜单

细心的你可能发现：例 3 的菜单条目用的是 <button> 而不是链接。 dropdown-item 两种都支持——条目若是跳转，就写在 <a href="…"> 上； 若是就地执行某个动作，写在 <button> 上更合适（演示里用它，是为了避免点击后页面跳走）。

更多变体：模态尺寸与下拉菜单的附件

模态框与下拉菜单的“尺寸、附属小件”也成体系。模态框改尺寸，只动 modal-dialog 这一个类；下拉菜单除了方向，还有右对齐、标题与分栏线：

类名加在谁身上效果
modal-sm / modal-lg / modal-xlmodal-dialog小 / 大 / 特大号弹窗
modal-fullscreenmodal-dialog铺满全屏；还有 modal-fullscreen-sm-down 等“小屏才全屏”的版本
dropdown-menu-enddropdown-menu菜单右对齐，适合放在页面右缘的按钮
dropdown-header / dropdown-divider菜单项容器里分区标题 / 一条分栏线
dropdown-toggle-split分割按钮的后半颗主按钮干活、小箭头只管开菜单

分割按钮（split button）是下拉菜单的常见搭配：主按钮执行“最常用的一招”， 旁边的小箭头才展开全部选项。结构上就是 btn-group 里并排两颗 btn， 第二颗带 dropdown-toggle dropdown-toggle-split。

练功 · 第十式
  1. 新建一个模态框：标题写“修炼心得”，modal-body 里放一个 <input class="form-control"> 输入框，页脚放“保存”与“取消”两个按钮。
  2. 把例 3 的下拉菜单改成向上弹出（提示：方向类加在容器上），再添加两个 dropdown-item。
  3. 思考题：关闭按钮只写 data-bs-dismiss="modal" 而不指定 id，为什么触发按钮却必须写 data-bs-target="#…"？
参考答案 1

modal-body 里放任何 HTML 都可以——表单、图片、列表，模态框照单全收。 form-control 是第八式学过的表单控件类，套上即得整洁的输入框样式。

参考答案 2

把例 3 容器上的 dropdown 类改成 dropup 即可：

方向类四兄弟：dropdown（向下）、dropup（向上）、 dropend（向右）、dropstart（向左）。真到了页面边缘空间不够时， Popper 会自动翻转方向，方向类只是“首选方向”。

参考答案 3

距离不同。关闭按钮自己就住在模态框内部：数据 API 顺着 DOM 树向上找， 总能找到最近的 .modal，所以只写 data-bs-dismiss="modal" 就够。 而触发按钮与模态框往往天各一方，没有任何父子关系可循，只能靠 data-bs-target="#id" 点名，双方才能对上号。

本式小结

  • 模态框三层结构：modal → modal-dialog → modal-content（header / body / footer）；
  • 触发用 data-bs-toggle="modal" + data-bs-target="#id"，关闭用 data-bs-dismiss="modal"；
  • modal-dialog-centered 垂直居中，modal-dialog-scrollable 框内滚动；
  • 尺寸只动一处：modal-dialog 上加 modal-sm/lg/xl/fullscreen；
  • 下拉菜单靠 data-bs-toggle="dropdown" 自动生效，分割线、禁用项与方向类各司其职；
  • dropdown-menu-end 右对齐、dropdown-header 分区标题、dropdown-toggle-split 分割按钮——菜单的“附件”也成体系。
