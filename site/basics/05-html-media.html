图片是静的，视频与音频是活的。HTML 早就不需要插件就能播放它们—— 这一式就把播放器请进页面，顺便说清浏览器给“自动播放”立下的规矩。

本式要点
  • 会用 video 与 audio，并用多个 source 做格式回退
  • 认得 controls、poster、preload、muted、loop 等属性
  • 知道自动播放的限制，不乱用自动播放
  • 会为视频配字幕轨（track），会用 iframe 安全地嵌入内容

视频：video 元素

播放视频只用 video 一个元素，配 controls 属性就能得到浏览器自带的播放条。 视频文件用 source 子元素引入，可以准备多个格式让浏览器挑：

这段约 2 秒的示例画面由本站用 ffmpeg 生成：两幅示意图之间的淡入淡出。

常用的属性都在下面这张表里：

属性 作用 说明
controls 显示播放控件 不写它，用户就没法播放（除非你在 JS 里自己控制）
poster 封面图 播放前显示的那一帧，给张有信息量的图体验更好
preload 预加载策略 none 不预载、metadata 只取时长等信息、auto 尽量预载
muted 静音开始 布尔属性；自动播放几乎都要靠它才被允许
loop 循环播放 适合短动画、氛围片段
playsinline 在页面内播放 iOS 上不加这个，视频往往会被强制全屏播放
width / height 预留尺寸 与图片同理，避免加载时页面跳动
心法：自动播放的三条硬规矩
  • 带声音的自动播放会被浏览器一律拦截——这是为了防止吓人一跳的广告；
  • “静音 + 自动播放”通常被允许，但移动端系统还可能再拦一道；
  • 所以：能不用自动播放就不用；必须用时，写 autoplay muted loop playsinline 四件套，并给用户一个暂停的方法。

音频：audio 元素

audio 与 video 的写法几乎一样，区别只是没有画面， 所以 width、height、poster 都派不上用场。 在页面上它显示成一条小巧的播放条。

例 2 · 音频播放器（点播放会听到一声轻响，音量已调低）

示例音频是 ffmpeg 合成的 1.8 秒纯音，用来说明 audio 的写法。

实际项目中，音频最常见的用途是播客与背景音。要记住两件事： 其一，永远不要偷偷自动播放背景音乐； 其二，纯音频内容要给文字版（听障读者与“不方便开声音”的场合都需要）。

给视频配字幕：track

track 是 video / audio 的子元素，用来挂字幕轨。 它的内容是 WebVTT 格式（.vtt）的纯文本文件——一条条时间轴加文字， 和唱片的歌词页差不多：

属性 作用
kind 字幕的类型：subtitles 翻译字幕、captions 含音效描述的字幕、descriptions 画面描述（供看不见画面的读者）、chapters 章节跳转
src WebVTT 文件的地址
srclang 字幕语言，如 zh、en
label 播放器里显示的语言名，如“中文”
default 默认启用这条字幕

例 1 的播放器里就挂着一条中文字幕：点开播放按钮，再把视频拉到后半段， 字幕会显示“山不让尘，川不辞盈”。给视频配字幕不是加分项，是及格线—— 它同时帮到听障读者、在嘈杂环境里看视频的人、以及需要翻译的读者。

已知限制：file:// 下字幕轨会被浏览器拦下

浏览器把每个 file:// 页面当成彼此隔离的“独立来源”， 因此双击打开本站时，字幕文件（.vtt）加载会被拒绝， 例 1 的字幕不会出现（播放器本身正常）。用 python3 -m http.server 起本地服务器或部署后再看，字幕即生效。 这与第三回第九式 Ajax 的限制同源，都来自浏览器的本地文件安全策略。

嵌入别人的内容：iframe

iframe（内联框架）能在你的页面里开一扇窗，窗外是另一个文档： 另一个网页、一张 SVG、一份文档，浏览器能显示的东西它基本都能装。 和图片一样，它需要几个必填的“说明”属性：

例 3 · 用 iframe 嵌一张会跟着窗口缩放的 SVG

窗口里的内容是一个独立文档：它有自己的滚动条，也不与外层共享样式与脚本。

属性 作用 备注
src 要嵌入的文档地址 站内用相对路径，站外用完整地址
title 这个窗口里是什么 必填：读屏软件靠它介绍这个框，缺失时等同于“无标题内容”
width / height 窗口尺寸 也可以用 CSS 控制
loading="lazy" 滚动到附近再加载 页面底部的地图、视频之类值得写上
sandbox 给嵌入内容加限制 嵌入不受信任的内容时使用，默认会禁用脚本与表单等能力，再按需放开
allow 授予特定权限 如 allow="fullscreen" 允许整屏
iframe 的两条注意事项
  • 它是“别人的地盘”：iframe 里的页面有自己的样式与脚本， 外层的 CSS 管不到它（反过来也一样），调试时要分别看；
  • 站外内容要谨慎：嵌入别人网站等于把那段内容交给对方控制， 对方挂了你的页面就空一块，所以重要内容不要只靠 iframe。

降级内容与历史包袱

例 1、例 2 里，video / audio 标签内部还写了一段文字。 那段文字只在浏览器不支持该元素时显示——今天的浏览器基本都支持， 所以它更像是给特例环境的“降落伞”。

另外两个元素偶尔还会遇到：object 与 embed。 它们能嵌入的东西更杂（PDF、Flash 时代的遗留物等），但控制力差、无障碍支持弱， 新项目要嵌内容，优先用 iframe。

还有一个老属性要避免：frameborder="0"。它是过时写法， 想去掉 iframe 的边框，用一句 CSS 就好：iframe { border: 0 }（第十九式会细讲边框）。

本式小结

  • video / audio 靠 controls 显示控件，靠 source 引入文件；
  • 常见属性：poster 封面、preload 预载、muted 静音、loop 循环、playsinline 页内播放；
  • 自动播放的限制针对的是“有声音”，但态度上应当能不用就不用；
  • track 挂 WebVTT 字幕，kind 有 subtitles / captions / descriptions / chapters；
  • iframe 嵌入其他文档，title 必填、loading="lazy" 按需、sandbox 保安全；
  • object / embed 属于遗留手段，新项目优先 iframe；frameborder 已过时，用 CSS。
练功 · 第五式
  1. 找一段你自己的视频（或先用例 1 的文件），写成带封面、双格式回退、中文字幕的播放器。
  2. 把一张 SVG（可用本站 assets/img/ 里的示例图）放进 iframe： 给它写 title，并让宽度占满容器（试试 width="100%"）。
  3. 思考：为什么浏览器敢拦截“带声音的自动播放”，却允许静音自动播放？这条规则保护的是谁？
参考答案 1

检查点：controls 在；两个 source 的 type 与文件类型一致； track 是最后一个子元素（规范建议放在 source 之后）； srclang 与 label 都写了。

参考答案 2

width="100%" 让窗口跟着容器宽度走。注意：嵌入的 SVG 自身若写死了宽度，就会在窗口里被裁切——这也是本站示例图写成 width="100%" + viewBox 的原因（见第四式的格式表）。

参考答案 3

它保护的是用户：网页往往在后台标签页、通勤路上、深夜的房间里被打开， 突然响起的广告音既打扰本人也打扰旁人。静音自动播放通常不会造成这种干扰， 所以被放过。记住这个立场的来源，就明白为什么“静音自动播放”也应当克制使用—— 它消耗流量、电池与注意力，而用户没要求看。
