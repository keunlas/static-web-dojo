造一个对象不难，难的是一次造一百个“长得一样、只是名字不同”的对象。 这一式讲的就是这件事：先做一副模具，再拿它批量生产—— 这副模具在 JavaScript 里有两种写法：老的“构造函数 + 原型”，新的 class。

本式要点
  • 知道 new 在后面做了哪四件事，明白“实例”与“原型”的关系
  • 会用 class 声明类：constructor、方法、get/set、static、私有字段 #
  • 会用 extends 与 super 做继承，知道 instanceof 怎么判断
  • 会处理 this：call / apply / bind，以及回调里丢失 this 的老问题

先看老写法：构造函数 + 原型

在 class 出现之前，JavaScript 是这样批量造对象的： 写一个函数，里面用 this 给实例挂属性；用 new 调用它； 方法则挂在函数的 prototype 上，让所有实例共享。

用 new 调用这个函数时，发生了四件事：

  1. 造一个空对象，并把它的原型指向 User.prototype；
  2. 把函数里的 this 绑定到这个新对象；
  3. 执行函数体（于是 this.name = … 挂到了新对象上）；
  4. 返回这个新对象——除非函数体显式返回了一个对象（那就会返回那个对象）。

于是就有了“原型链”：实例自己没有的属性，会沿着 实例 → User.prototype → Object.prototype → null 一路往上找。 instanceof 也是沿着这条链判断的。

      演示里有一行值得多看两眼：t1["#secret"] 读出来是 undefined—— 因为 #secret 不是一个普通的属性名， 用方括号配字符串去“猜”它，什么也拿不到； 而真正写成 t1.#secret 的话，浏览器在解析阶段就报语法错误， 脚本根本跑不起来。私有字段的私有，是语法级别的私有，不是靠约定。

      class 与构造函数的三点不同
      • 不能提前用：类声明也有“暂时性死区”，在 class 之前 new 它会报 ReferenceError（而函数声明是可以提前调用的，第二十八式）；
      • 不能用普通函数的方式调用：Trainee("墨白")（不加 new）会报 TypeError: Class constructor cannot be invoked without 'new'；
      • 类体里永远是严格模式，而且类的方法默认不可枚举—— 因此 for…in 不会翻出方法来（构造函数原型上的方法会）。

        经验：组合往往比继承更好用

        继承适合“确实是一种”（教练确实是一种成员）； 但当层次变深、“到底该继承谁”开始纠结时，通常说明该换成组合： 把能力做成小对象或函数，需要谁就“装”给谁 （比如 canTeach(coach)、把 logger 作为参数传进去）。 JavaScript 只支持单继承，这一条建议在真实项目里帮你避开的坑比你想的多。

        this 的三种“搬运”方式：call / apply / bind

        this 由“怎么调用”决定（第三十一、三十三式）， 而这三个方法可以临时指定它：

        方法 怎么传参 返回什么 典型用途
        fn.call(thisArg, a, b)参数一个个写函数的返回值借用方法、一次性指定 this
        fn.apply(thisArg, [a, b])参数放数组函数的返回值把数组当成参数表传进去
        fn.bind(thisArg, a)可预先固定部分参数新函数（this 被锁住）给回调绑定 this（事件处理里最常见）

            本式小结

            • new 做了四件事：造对象、绑 this、执行函数体、返回对象；
            • 属性写在实例上、方法挂在原型上；原型链让实例“借到”方法，instanceof 顺着链判断；
            • class 是原型写法的语法糖，但更严格：不能提前用、不能不加 new 调用、类体自动严格模式、方法不可枚举；
            • 类的零件：constructor、方法、get/set、static、私有字段 #；
            • 继承用 extends，构造函数里先 super()，重写时可 super.方法() 复用父类实现；
            • call / apply / bind 用来指定 this， 其中 bind 返回新函数，是回调场景的主力；
            • 方法被摘出来单独调用会丢 this；修法有二：bind 绑定， 或用箭头函数包一层（箭头函数沿用外层的 this）；
            • 继承不是唯一出路：层次一深就该考虑组合。

            参考答案 3

            首先是省内存：一千个实例只存一份方法，而不是一千份。 其次（也是更重要的）是一致性：方法只有一处，改一次全体生效—— 演示里“改了原型上的方法，所有实例立刻跟着变”就是这个意思； 如果每个实例各存一份，就得一千次修改，漏改任何一处都会长出“行为不一致的怪对象”。 第三个好处是可检查性：instanceof、 Object.hasOwn、原型链都建立在“属性在实例、方法在原型”这条分工上， 调试时能一眼看出“这个能力是这一类东西共有的，还是这一个实例特有的”。
