跳到正文

布局的本事，说白了就三件事：元素怎么排、往哪偏、谁盖谁。 这一式讲的就是这三件事：display 决定排法， position 决定偏移，z-index 决定层叠次序。

本式要点
  • 分清 display 的常见取值，特别是 none 与 visibility: hidden 的区别
  • 掌握 position 五种取值：各自“相对谁偏移”、是否脱离文档流
  • 会做绝对定位角标与居中，理解“最近的非 static 祖先”这条规矩
  • 知道 z-index 什么时候生效、层叠上下文是怎么创建出来的
  • 看懂浮动与清除浮动（历史但常见），知道现代替代方案是 flex / grid 与 flow-root

display：元素怎么排

display 决定元素“以什么样的盒子参与排版”。常用的这些：

取值 行为 典型用途
block独占一行，可设宽高div、p、h1 的默认值
inline跟文字排在一行；宽高与竖直边距无效span、a、strong 的默认值
inline-block跟文字排在一行，但内部按盒子处理标签、按钮、小卡片
none完全不生成盒子：不占位置，读屏软件也不会读隐藏内容、折叠面板
flow-root块级容器，并新建一个“独立排版环境”（BFC）包住浮动子元素、阻止父子边距折叠
flex / inline-flex弹性容器（第二十一式）一行、一列、居中对齐、自动分配空间
grid / inline-grid网格容器（第二十二式）二维布局
contents自身盒子“消失”，子元素提升到父层参与排版去掉无意义的中间层；无障碍支持要实测

隐藏的三种做法要分清：display: none 是“根本不存在”（不占位、读屏不读）； visibility: hidden 是“看不见但还在”（占位、读屏也不读）； 而 opacity: 0 是“全透明”（占位、仍能被键盘聚焦、读屏也读得到）—— 三者用途完全不同，选错会带来焦点错乱或“幽灵按钮”。

position：往哪偏

五种定位方式的核心差别只有两条：相对谁偏移、还占不占原来的位置。

取值 相对谁偏移 脱离文档流？ 留在原位的空间？ 常见用途
static 不偏移（top 等无效） 否 是 默认值，什么都不用写
relative 自己原来的位置 否 是（原位置仍占着） 微调位置；给子元素当参照
absolute 最近的“非 static 祖先”（都没有则初始包含块） 是 否 角标、关闭按钮、下拉菜单、遮罩
fixed 视口（浏览器窗口） 是 否 顶栏、悬浮按钮、回到顶部
sticky 先按普通流排；滚动到阈值后“粘住” 否 是 吸顶表头、吸顶侧栏

偏移用 top / right / bottom / left 控制， 也可以用简写 inset: 0（四边都 0）。 absolute 有一个新手必踩的坑：它找的是“最近的非 static 祖先”—— 父元素忘了写 position: relative，它就会一路往上找到更外层的容器甚至页面根，位置自然就“乱跑”了。

z-index 与层叠上下文

元素重叠时，谁在上面？规则比想象中细，先记住三条：

  • z-index 只对定位元素（position 不是 static）与 flex / grid 子项生效，写在普通块上没用；
  • 它是整数、不带单位，可以是负数；
  • 比较只在同一个层叠上下文里进行——不同上下文里的数字没法直接比大小。

下面这些属性会“创建新的层叠上下文”（常见的几项）：

触发条件 说明
position: relative/absolute + z-index 不是 auto最传统的一种
position: fixed / sticky现代浏览器里它们本身就会创建
opacity 小于 1做淡出动画时常见的“意外副作用”
transform / filter 不是 none做了位移、缩放的盒子会自成一层
isolation: isolate专门用来“我要一个干净的层叠上下文”
例 4 · 层叠上下文：外面 z-index 更小，却依然盖得住里面
外层（z-index: 1，且带 opacity: .99） 内层 z-index: 9999，但它被关在外层的上下文里
另一个块：z-index: 2，盖在外层之上

结果就是：内层虽然写着 z-index: 9999，但它被限制在外层的上下文里， 整个外层只有 1 ——所以红色块（2）照样压在它上面。 这解释了那句老经验：“加了 z-index 还是被盖住”， 多半是层叠上下文在作怪，而不是数字不够大。 顺便记一条纪律：不要用 z-index: 9999 解决问题，先弄清楚它在哪个上下文里。

float 与 BFC：历史包袱与它的现代解法

浮动（float）最初是为“文字环绕图片”设计的，后来被拿来做过整套页面布局， 于是留下了两个经典问题：文字环绕与父容器高度塌陷。

问题 现象 现代解法
父容器塌陷 子元素都浮动了，父元素高度算成 0，背景与边框“包不住”它们 给父元素 display: flow-root（首选）或 overflow: hidden； 老写法是父元素 ::after 清浮动
多栏错位 下一个元素被浮动挤到旁边，或换行位置飘忽 给受影响元素 clear: both；整栏布局改用 flex / grid
想做一行排列 用浮动凑高度、凑间距，越写越碎 display: flex + gap（第二十一式）

本式小结

  • display 决定盒子怎么参与排版；none 不占位， visibility: hidden 占位但不可见，opacity: 0 可聚焦可朗读；
  • position 两问定生死：相对谁偏移、还占不占原位； absolute 找最近的非 static 祖先，忘了给父元素定位就会“乱跑”；
  • 居中三招：已知宽高 inset: 0 + margin: auto；未知宽高 left/top: 50% + translate(-50%,-50%)；最省心是 flex 居中；
  • sticky 要三个条件：写阈值、祖先不裁剪、容器能滚动；
  • z-index 只对定位元素与 flex/grid 子项生效，比较只在同一层叠上下文内进行；
  • opacity、transform、filter、fixed/sticky 都会悄悄创建层叠上下文；
  • 浮动会塌陷父容器，现代解法是 flow-root；整栏布局请用 flex / grid。
练功 · 第二十式
  1. 做一张“卡片 + 角标”：卡片右上角挂一个“新课”角标， 左下角再放一个绝对定位的小按钮（提示：用 bottom 与 left）。
  2. 做一个可滚动列表，让第一行在滚动时粘在顶部；再故意给它的祖先加上 overflow: hidden，看看吸顶为什么失效。
  3. 思考：为什么“把子元素的 z-index 调到 9999 反而盖不过外面的元素”？ 请用自己的话解释“层叠上下文”。
参考答案 1

关键就是父元素那句 position: relative； 去掉它，两个小家伙会一路找到更外层的容器，位置立刻跑偏—— 这正是最该亲手试一次的“反例”。

参考答案 2

原因：sticky 是相对“最近的滚动容器”粘住的。 祖先一旦设了 overflow: hidden，这个祖先就成了新的裁剪/滚动容器， 它自己并不滚动，于是元素没有可粘的地方，看起来就和普通元素一样。

参考答案 3

因为 z-index 只能在同一个层叠上下文内部比大小。 可以把每个层叠上下文想成一只“盒子”：盒子里所有元素先自己排好序， 然后整个盒子作为一个整体，去和外层的元素比。 子元素写在盒子里的 9999，只决定它在盒子里的位置； 而盒子本身在外层的顺序可能很小（比如 1），于是照样被外层的 2 压住。 所以正确做法不是加大数字，而是找出是哪条属性（opacity、 transform、position: fixed 等）创建了这一层， 再从结构上调整。
