数组是把同类东西排成队，对象则是给东西贴上名字： 名字 + 值，成对出现。这一式讲清对象的读写与复制， 再补上两位更专门的容器——Map 与 Set。

本式要点
  • 会创建与读写对象，分得清点号与方括号的用法
  • 会用解构与展开，知道“复制”在对象上意味着什么（浅复制）
  • 认得 Object.keys/values/entries/fromEntries/assign/freeze/hasOwn
  • 会用 Map 与 Set 解决对象与数组解决不好的问题
  • 会用 JSON.stringify 与 JSON.parse，并知道它们会丢什么

    解构与展开

    例 2 · 解构、合并与“浅复制”的真相
      浅复制：最常见的一类“意外联动”

      { ...obj } 与 Object.assign({}, obj) 都只复制第一层： 里面如果装着对象或数组，副本与原对象仍然共享它们。 改副本的嵌套字段，原对象也跟着变——演示里那一步正是如此。 需要彻底独立的一份时用 structuredClone(obj)（现代浏览器已支持； 它不能复制函数与 DOM 节点，遇到会抛错）。

      Object 静态方法速查

      方法 做什么 注意
      Object.keys/values/entries(obj)取出键 / 值 / [键, 值] 数组只取自己的、可枚举的属性
      Object.fromEntries(pairs)把 [键, 值] 数组变回对象常与 entries + map 配对使用
      Object.assign(目标, …来源)把来源的属性合并进目标会修改并返回目标；要新建就写 Object.assign({}, a, b)
      Object.hasOwn(obj, key)是不是自己的属性比 obj.hasOwnProperty(key) 稳（后者可能被覆盖）
      Object.freeze(obj)冻结：不能增删改属性浅冻结；严格模式下修改会报错，非严格模式静默失败
      Object.isFrozen(obj)是否已冻结常与 freeze 配套做自检
      Object.seal(obj)封闭：能改不能增删比 freeze 松一档
      Object.entries(obj).map(…)遍历并变换对象想“把对象里的值统一处理”时最顺手

        Map 与 Set：两种更专门的容器

        对象很好用，但它有两个限制：键只能是字符串或 Symbol， 而且它身上还带着一堆“继承来的属性”（比如 toString）。 需要“用对象当键”“按插入顺序遍历”“随时知道有几项”时，就该请出 Map；而 Set 则是“不重复值的集合”，去重与判重最拿手。

        常见用途描述一个“东西”键值映射、缓存、计数去重、判重、集合运算
        例 4 · Map 当计数器、Set 去重与集合运算

          一段经验：“描述一个东西”用对象，“查表 / 计数 / 存任意键”用 Map， “去重 / 判重”用 Set。 另外 WeakMap / WeakSet 的键是“弱引用”—— 对象没人再用时会被自动回收，常用来给 DOM 元素挂额外数据而不担心内存泄漏， 但它们不能遍历、也没有 size。用到再回查即可。

          JSON：把数据变成字符串，再变回来

          数据要在页面之间传递（比如存进 localStorage、发给服务器）， 都得先变成字符串。JSON 就是这套“文本格式”的通用语—— 它长得像 JavaScript 的对象字面量，但不是 JavaScript： 键必须用双引号、不能有注释、不能写函数，也不能有 undefined。

            本式小结

            • 对象是键值对的集合；读固定名字用点号，动态键用方括号；delete 删属性；
            • in 会查原型链，Object.hasOwn 只查自己的； Object.keys/values/entries 只列自己的可枚举属性；
            • 方法里的 this 看“怎么调用”：摘出来单独调用就不再指向原对象；
            • 解构能改名、给默认值、嵌套取值、收集剩余属性；展开用来复制与合并（后者覆盖前者）；
            • 展开与 Object.assign 都是浅复制；要彻底独立用 structuredClone；
            • Object.freeze 是浅冻结，严格模式下写被冻结的属性会报错；
            • 查表 / 计数 / 任意键用 Map，去重与判重用 Set，描述一个东西用对象；
            • JSON 是数据交换的通用格式：函数与 undefined 会被丢掉、NaN 变 null、日期变字符串、 循环引用会抛错；解析非法 JSON 也会抛错——所以 JSON.parse 常要配 try…catch。

            1. 写一个对象 book（书名、作者、页数、标签数组）， 用解构把书名与作者取出来，再用展开复制一份并修改页数，最后打印两份做对比。
            2. 有一段打卡记录 ["周一", "周三", "周一", "周五", "周三"]： 用 Map 统计每个星期几出现了几次，用 Set 列出共有哪几天打过卡。
            3. 思考：const settings = { theme: "light" }; 之后 settings.theme = "dark" 是合法的；但 Object.freeze(settings) 之后再改就会报错。为什么要有“冻结”这种能力？

            参考答案 3

            因为“不会被改”本身就是一种信息：写代码的人看到冻结过的对象， 就知道可以放心把它交给别人、缓存起来、反复复用，而不必担心某个角落把它悄悄改掉。 典型场景有三类：常量配置（全年不变的主题色表）、 共享给多个模块的对象（谁改了都不知道）、 以及冻结后能带来性能优化的场景（某些引擎对不变对象优化得更好）。 记住它的局限：冻结是浅的，里面嵌套的对象照样能改； 所以真正的“不可变数据”要么逐层冻结，要么靠团队约定与工具库来保证。
