跳到正文

网页不光给人看，也要听人说话——登录、搜索、留言、下单，全靠表单把读者的意思收进来。 这一式的目标很朴素：把一次对话的入口搭对。

本式要点
  • 知道 form 的 action、method 各管什么，GET 与 POST 有什么区别
  • 会给每个输入框配 label，并说清它为什么不是可选项
  • 认得文本类 input 的几种类型与常用属性（name 是重中之重）
  • 分得清 submit / reset / button 三种按钮

表单里有两个角色

写表单时要同时照看两个人：坐在屏幕前的人要看得懂、点得准； 机器（浏览器与服务器）要知道每一格填的是什么、送到哪里去。 所有容易踩的坑，几乎都是只顾了一个角色。

先交代一句本站的现实：这是一个纯静态站点，没有后端服务器。 表单填完之后把数据送到哪里、怎么保存，需要后端或第三方服务—— 这超出了本教程的范围。所以教程里的演示只做两件事： 把结构与校验教对，以及在需要时用一小段脚本拦住提交、就地显示结果。

form 与提交：action 与 method

form 是整个表单的容器，两个属性决定“提交”这件事怎么发生：

属性 作用 常见取值
action 数据送到哪个地址 后端接口地址；留空表示提交给当前页面
method 用什么方法送 get（默认）或 post
enctype 数据的编码方式 有文件上传时必须用 multipart/form-data
target 提交后在哪里显示结果 _blank 新窗口等，与链接的 target 同理
novalidate 关闭浏览器自带的校验 想自己写校验提示时才用（第八式细说）

GET 与 POST 的区别，用一张表就能说清：

method="get" method="post"
数据放在哪 拼在网址后面：search.html?q=站桩 放在请求体里，网址上看不到
适合什么 搜索、筛选这类“看一眼就好”的查询 登录、注册、下单这类“会改变数据”的提交
能收藏/分享结果吗 能——网址里带着条件 不能，刷新还可能重复提交
安全性 参数暴露在网址与历史记录里，不能放密码 不暴露在网址上，但不代表加密——加密靠 HTTPS

label：每个输入框都该有个名字

label 是输入框的“名牌”，两种写法都合法：

  • 显式绑定：<label for="user"> 与 <input id="user"> 用 for 和 id 对上暗号；
  • 包裹式：把 input 直接放进 label 里面。

带 label 的输入框能多得到三样东西： 点标签文字就能聚焦输入框（小屏与触屏上体验差别很大）； 读屏软件会念出“用户名，编辑框”而不是“编辑框”； 以及给屏幕阅读器的用户一个可靠的“填到哪了”的线索。

心法：placeholder 不是标签

placeholder 只是淡淡的示例文字，一开始输入就消失， 读屏软件对它的朗读也不可靠。它永远不能代替 label—— 可以把 label 想成门牌号，placeholder 想成贴在门上的便签。

文本类输入框与常用属性

input 的能力靠 type 切换。先看文本家族：

type 用途 手机上会怎样
text单行文本，默认值普通键盘
search搜索词键盘上常带“搜索”键，部分浏览器给一个清除小叉
email邮箱地址键盘带 @ 与 .
tel电话号码弹出数字键盘（注意：tel 不做格式校验）
url网址键盘带 / 与 .com
password口令输入内容被隐去
number数字（可带上下微调按钮）数字键盘

选对 type 是“免费赚到”的体验：手机上键盘不同、浏览器还能顺手做校验。 接下来是属性表，前四个是重点：

属性 作用 备注
name 这一格数据叫什么名字 没写 name 的输入框，提交时数据会被丢弃（最常见的白干原因）
value 初始值（或提交时携带的值） 用户改了，就以用户填的为准
required 必填 布尔属性；留空提交时浏览器会拦下并提示
autocomplete 自动填充提示 如 name、email、new-password，帮用户少打字
placeholder 灰字示例 不能代替 label
readonly 只读 可以选中复制，会随表单提交
disabled 禁用 变灰、不能聚焦，不会提交；读屏软件也会跳过
maxlength / minlength 长度上限 / 下限 下限在提交时校验，上限在输入时就拦住
pattern 用正则限定格式 如邮编：pattern="\d{6}"（第八式会用起来）
autofocus 进页面就聚焦 一个页面最多用一次，别抢用户的注意力

例 2 · 文本家族各就各位






按钮：提交、重置、普通按钮

按钮用 button 元素写，type 决定它的身份：

  • type="submit"：默认类型，提交表单（等于按下回车）；
  • type="reset"：把表单里的字段恢复成初始值（不是清空，是回到初始值）；
  • type="button"：什么也不做，留给你自己写脚本用。

老写法 <input type="submit" value="提交"> 也能用， 但它显示的文字来自 value，且不能包含图标等子元素， 新代码统一用 button。

心法：三个最容易白干的错误
  • 输入框忘了写 name——用户填得再认真，提交时也不带它走；
  • 用 placeholder 当标签——输入一多，用户就忘了这一格要填什么；
  • 口令框不给 name 却写 autocomplete="current-password" 这类矛盾配置——密码管理器会认不出来。

本式小结

  • form 用 action 说明送到哪、用 method 说明怎么送；
  • 查询用 GET（参数在网址上，能收藏分享），会改数据用 POST（参数在请求体里）；
  • 每个输入框都要有 label（for + id 或包裹式），placeholder 不能替代它；
  • 输入框必须写 name，否则数据会被丢弃；type 选对能免费换来合适的键盘与校验；
  • required、autocomplete、readonly、disabled、maxlength、pattern 各司其职；
  • 按钮三兄弟：submit 提交、reset 恢复初始值、button 交给脚本。
练功 · 第七式
  1. 做一个“报名表单”：姓名（必填）、邮箱（必填）、电话（可空但格式要对）， 每个字段都要有 label 与 name，并配一个提交按钮。
  2. 把上一题的表单改成 GET 提交，猜一猜提交后网址会变成什么样； 再想想：换成 POST 会有什么不同？
  3. 思考：为什么 disabled 的字段不会提交，而 readonly 的会？ 这两种状态各自适合什么场景？
参考答案 1

检查点：三个 label 的 for 与对应 id 一致； 三个字段都有 name；必填项写了 required； 电话用了 pattern（可留空，留空不触发校验）。

参考答案 2

GET 提交后，网址会变成类似 signup.html?name=墨白&email=mo%40example.com&tel= ——所有字段拼在问号后面，特殊字符被转义（@ 变成 %40）。 POST 提交时网址不变，数据放在请求体里发给 action 指定的地址。 所以：报名这种会“留下记录”的提交应该用 POST；而且真正的表单提交都需要一个 接收数据的服务器地址——纯静态页面上，按下按钮只会跳到 action 那张页面。

参考答案 3

因为两者的含义不同：disabled 表示“这个字段此刻不参与”， 所以浏览器既不提交它，也把它从交互与朗读里拿掉； readonly 表示“能看不能改”，值仍然有意义，因此照常提交。 典型用法：readonly 放订单号、只读金额这类要一起提交的值； disabled 放“尚未满足条件前不允许填写”的字段（例如未选套餐前的子选项）。
