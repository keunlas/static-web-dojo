跳到正文

有些信息天生就长着横竖两个方向：课表、价目单、对战记录。 把它们塞进段落里是折磨读者，这时候就该请出表格——HTML 里唯一为“二维数据”准备的元素。

本式要点
  • 会用 table、tr、th、td 搭出行与列
  • 会用 caption 写表名，用 thead / tbody / tfoot 分组
  • 明白 th 与 scope 是给读屏软件用的“指南针”
  • 会用 colspan 与 rowspan 合并单元格，并保持格子总数不出错

行与列：表格的基本结构

规则只有三条，记牢就不会写乱：

  • table 是整张表；
  • tr（table row）是一行；
  • 行里的每个格子是 td（table data），表头格子用 th（table header）。

也就是说，表格的书写顺序是一行一行写， 每行里按从左到右写格子——和你在纸上画表的方向完全一致。

例 1 · 最小的表格：一行表头 + 两行数据
招式 要点
站桩 沉肩坠肘，气息平稳
出拳 力从地起，出于腰背

注意每行的格子数量要一致：例 1 每行都是两个格子。少写或多写一个， 表格就会出现看不见的错位——这是排查表格时的第一号线索。

表名与行组：让表格有“目录”

数据一多，光看格子就不够了。HTML 给表格准备了四样零件来补充说明：

元素 作用 写法上的讲究
caption 表格的标题（如“修行日程表”） 必须是 table 的第一个子元素；写它比在外面写个标题更“绑定”
thead 表头区（那一行标题格子） 滚动长表格时，浏览器可以让表头保持可见
tbody 数据主体 可以写多个 tbody 给数据分组
tfoot 表尾，通常是合计、备注 按规范写在 tbody 之后

推荐的书写顺序是：caption → colgroup（可选，稍后讲）→ thead → tbody → tfoot。 不写 tbody 时浏览器会自动替你补一个，但显式写出来结构更清楚。

例 2 · 带表名、表头、表尾的日程表
本周修行日程
日期 功课 时长
周一 抄写页面骨架 30 分钟
周三 拆解一个喜欢的网页 45 分钟
周五 写一页自己的介绍 60 分钟
合计 135 分钟

这张表里有两个细节值得单独说：

  • 第一列的日期也用了 th：它其实是每一行的“行首标签”， 所以用表头格子，并配 scope="row" 说明“我管的是这一行”；
  • scope 是给读屏软件的路标：有了它，读屏软件读到 “45 分钟”时能念出“周三 · 时长：45 分钟”，而不是孤零零一个数字。 表头格子写 scope="col"，行首格子写 scope="row"。

合并单元格：colspan 与 rowspan

两个格子内容相同、可以并成一个时，就用得上合并： colspan 横着并（跨几列），rowspan 竖着并（跨几行）。 值都是正整数，表示“占几个格子”。

这里有个新手最容易犯的错：合并之后，后面的行要少写对应数量的格子。 因为格子总数是固定的——你多了占位，别人就要让位。把每一行的格子数加起来核对一遍， 是检查表格的正确方法。

例 3 · 一张课表：同一时段跨两行，同一天跨两列
练功房课表
时段 周一 周二
晨课 基本功集训 桩功
午课 拳法
晚课 自由练习（全场地开放）

数一数就明白了：第二行只写了两个格子（“午课” + “拳法”）， 因为周一那一格被上一行的 rowspan="2" 占住了。 合并让表格更紧凑，但也更容易数错——格子多的时候，宁可先画一张草图。

心法：表格不多了，也别省 td

空着的格子也要写出 <td></td>，不能省略标签。 省掉一个格子，后面所有格子都会向前挤一格，整张表就错位了。

什么时候不该用表格

在很久以前，网页开发者用表格来排页面布局——“左边一列导航、 右边一列内容”就是两张表格嵌套出来的。那个时代已经过去了：

  • 表格的语义是“二维数据”，用它布局会让读屏软件把整个页面念成一张表；
  • 表格的默认行为（自动分配宽度、按内容撑开）本来就不适合布局；
  • 排布局现在有 Flex 与 Grid 两把利器（第二十一、二十二式），表达能力远超表格。

判断标准很简单：内容可以念成“第几行第几列”吗？ 可以，就用表格；不可以（只是想让东西左右排开），就用 CSS。

本式小结

  • 表格按行写：table → tr → th / td，每行格子数要一致；
  • caption 写表名（放在最前），thead / tbody / tfoot 分区；
  • th 配 scope="col" 或 scope="row"，给读屏软件指路；
  • colspan 横着并、rowspan 竖着并，合并后要在后续行少写格子；
  • 空格子也要写 <td></td>；
  • 表格只用来放数据；页面布局交给 CSS 的 Flex 与 Grid。

  2. 做一张两行两列的小课表，把“周一上午”两节课合并成一个格子（提示： 需要 rowspan 还是 colspan？）。

用表格布局时，读屏软件会把页面当成一张巨大的数据表来念， 不断报出“第 3 行第 2 列”这类信息，读者根本听不出哪里是导航、哪里是正文； 而正确的语义（导航用 nav、正文用 main、 真数据才用 table）能让读屏软件用快捷键按“地标”跳转。 结构对了，机器才帮得上忙——这是第九式与第十一式的主题。
