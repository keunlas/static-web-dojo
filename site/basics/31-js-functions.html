前面几式的代码都是“从头写到尾”。但真实项目里，同一段逻辑要反复用、还要按需调整—— 这时就该把它装进一个盒子，起个名字，随时取用。这个盒子就叫函数。

本式要点
  • 会用三种函数写法，知道“函数声明会提升、函数表达式不会”
  • 会用参数默认值、rest 参数与提前 return，写出好用的函数
  • 说清全局、函数、块级三层作用域与“就近查找、同名遮蔽”
  • 理解闭包：函数记住了它出生时的环境，因此能做计数器与私有变量
  • 认识递归、回调与 this 的初步规则

三种写法，一个身份

写法 样子 特点
函数声明 function greet(name) { … } 会被“提升”：可以在定义之前调用；适合写模块里的主要函数
函数表达式 const greet = function (name) { … }; 赋值之后才存在；写法灵活（可以放进对象、当作参数传）
箭头函数 const greet = (name) => `你好，${name}`; 最短；没有自己的 this；适合回调与小工具

新手最常问“到底用哪个”，可以照这个顺序挑： 要单独给一段逻辑起名 → 函数声明； 当成值来传递（回调） → 箭头函数； 需要用到 this 指向调用者 → 用 function 写法 （为什么，本节最后会讲）。

例 1 · 提升：函数声明能“提前上岗”，函数表达式不行

    演示里那句 typeof expressed 得到的是 "undefined"： 用 var 声明的名字会被提升（存在但值是 undefined）， 所以能安全地“问一问”；而如果用 const expressed = …， 在赋值前访问会直接报错（暂时性死区，第二十八式）。

    参数与返回值

    参数是函数的“输入口”，返回值是“输出口”。几个实用的写法：

    两个细节值得知道：其一，实参多于形参时多出来的会被忽略 （但可以用 arguments 或 rest 参数接住）； 其二，函数内部的 arguments 是一个“像数组但不是数组”的东西， 现代写法一律用 rest 参数代替它，箭头函数里更是没有 arguments。

    例 2 · 默认参数、rest 参数与守卫式返回

      作用域：变量的可见范围

      JavaScript 的作用域有三层，从外到内是： 全局（整个脚本）、函数（函数体内部）、 块级（{ } 之内，只有 let/const 认这个界）。

      • 就近查找：用到一个名字时，先从最近的一层找，找不到才往外层找；
      • 同名遮蔽：内层声明了同名的变量，外层的就被“挡”住了—— 在里层看不到外层的它；
      • 别污染全局：脚本顶部随手写的 let data = … 会和页面其它脚本的名字打架。栈越浅越好，用函数把逻辑包起来。
      例 3 · 三层同名变量，看看到底读到哪一个

        闭包：函数记得它出生的地方

        当一个函数在另一个函数里被创建，它就会“记住”外层函数里的变量—— 即使外层函数已经执行完毕，这些变量依然活着，只有这个内层函数能碰它们。 这就是闭包。它不是语法特性，而是“作用域 + 函数是值”自然产生的结果。

        例 4 · 闭包现场：计数器，以及 var 与 let 的差别
          闭包不是免费的

          被闭包“记住”的变量会一直留在内存里。 偶发的计数器、事件处理函数完全没问题； 但如果在循环里给成千上万个元素各绑一个闭包，或者把大数组塞进闭包里长期持有， 内存就会一路涨。第三十八式讲事件绑定时会再遇到这个话题。

          递归与回调：把函数当积木

          递归是“函数调用自己”，写起来优雅，但必须有终止条件， 否则栈会溢出（报 RangeError: Maximum call stack size exceeded）。 回调则是“把函数当参数交给别人，等时机到了再调用”—— 这是 JavaScript 里最常见的协作方式：forEach、map、 事件监听、定时器，收到的都是回调。

          例 5 · 递归阶乘，以及把函数当参数传递（高阶函数）

            递归解决“结构自相似”的问题（目录树、嵌套评论都适合）， 但能用循环表达的简单重复就别用递归——循环更好读，也不担心栈的深度。

            this 初步：函数里的“我”是谁

            this 是函数被调用时自动获得的一个变量，指向“谁在调用它”。 规则不复杂，先用三条保住日常：

            调用方式 函数里的 this 例子
            作为对象的方法调用 那个对象 cat.say() 里 this 是 cat
            直接调用（严格模式） undefined say() 单独跑，this 是 undefined
            箭头函数 没有自己的 this，用外层的 回调里写 () => … 往往正是为了避免 this 出问题

            这一段现在只需要“见过”：第三十五式讲类与对象时会展开， 第三十八式讲事件时会遇到“回调里的 this 不是元素”这个真实坑。 记住一句话就够：要 this 用 function，不要 this 用箭头。

            本式小结

            • 三种写法：函数声明（会提升）、函数表达式、箭头函数（没有自己的 this）；
            • 默认参数只在“没传或传 undefined”时生效；rest 参数 ...nums 收成真数组， 取代老式的 arguments；
            • 守卫式返回（提前 return）能让函数体少一层缩进、读起来更顺；
            • 作用域三层：全局 / 函数 / 块级；就近查找、同名遮蔽；逻辑尽量包进函数，别污染全局；
            • 闭包＝函数记着出生时的环境：能做计数器与私有变量，也解释了“循环里 var 与 let”的差别；
            • 递归必须有终止条件；回调与高阶函数是 JavaScript 的日常，map/filter 就是它们；
            • this 看调用方式：方法调用指向对象、直接调用在严格模式下是 undefined、 箭头函数用外层 this。

            参考答案 1

            要点：average 里先用 scores.length === 0 挡住“空数组除以 0”的情况 （否则会得到 NaN）；这就是守卫式返回的实用价值。

            参考答案 2

            检查点：total 在函数外无法访问（闭包的“私有变量”效果）； 调两次 makeAccumulator() 会得到两份独立的状态—— 每次调用外层函数，都会创建一套新的变量环境。

            参考答案 3

            因为 var 是函数作用域：整个循环只用同一个 i， 循环结束时它的值是 3（i < 3 的最后一个不成立值）。 三个函数都是闭包，记住的是同一个变量， 所以调用时读到的都是最后那个 3。 换成 let 之后，每执行一轮循环体会创建一个新的块级变量， 三个闭包各记住自己那一轮的 i，于是依次得到 0、1、2。 一句话：闭包记住的是“变量”，不是“值”；变量有几个，取决于作用域怎么划。
