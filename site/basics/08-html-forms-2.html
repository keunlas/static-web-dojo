上一式搭好了对话的入口，这一式把剩下的对话方式补齐： 让读者在选项里挑、在多行框里写、从日历上选一天，最后再由浏览器帮忙把明显的错误拦在门口。

本式要点
  • 会用单选 radio、复选 checkbox，并说清“同名互斥”是怎么来的
  • 会用 select / optgroup / option 与 datalist、textarea
  • 认得日期、颜色、范围、文件等专用控件，以及 file 的两个专属属性
  • 会写 fieldset / legend 分组与约束校验（required、pattern、min / max）

单选与复选：选择类控件（一）

一组选项里只能选一个，用 radio（单选框）；可以同时选多个，用 checkbox（复选框）。它们和上一式的文本框不一样，有三个地方要特别留意：

  • 靠 name 分组：同一组单选必须写相同的 name， 浏览器才会让它们互斥；名字不同就各选各的；
  • 靠 value 提交：选中后提交的是 value， 所以每个选项都要写清 value，别用“选项一”这种含糊值；
  • 靠 label 点击：单选框很小，点字比点框容易得多； 用 for + id 把它们绑起来（第四式的图注讲过同样的道理：结构对，体验自然对）。

下拉框与候选项（二）

select 是“从列表里挑值”，三种形态各有用途：

写法 外观与用途 要点
<select> 点开才展开的下拉框，省地方 选项用 option；默认选中第一个
<select multiple> 直接铺开的列表，可多选 配合 size 指定显示几行；多选时要按住 Ctrl / Cmd
<optgroup label="…"> 给选项分组 只能包 option，不能嵌套别的组
<datalist> 可输入也可挑的推荐列表 配 <input list="id"> 使用；它只是建议，不限制输入

多行文本与其它文本控件

textarea 是多行输入框，有一处和 input 截然不同： 它的初始值写在标签之间，而不是 value 属性里。

属性 作用 备注
rows / cols 初始显示几行、几列宽 只是初始视觉尺寸，用户可以拖动右下角改变
maxlength / minlength 字数上下限 中英文都按字符数算
wrap 换行方式 默认 soft（显示换行、提交不换行）；hard 会让提交内容也带换行，需同时写 cols
spellcheck 拼写检查 英文内容可留默认，代码或专名多的框建议 spellcheck="false"

另外两个常被忽略的元素：output（显示计算结果，如滑块当前值） 与 progress / meter（进度条与刻度尺，前者表示“任务进度”，后者表示“某个量落在哪一档”）。

日期、颜色、范围与文件

现代浏览器给了一批“专用输入框”，写对了 type 就白得一整套选择器界面：

type 用途 值得记的细节
date年-月-日提交格式固定为 2026-09-14，与你所在地区的显示方式无关
time时:分格式为 06:30，可加 step 控制秒
datetime-local日期 + 时间，不含时区适合“预约到店”这类场景
month / week只选月 / 只选周如信用卡有效期、排班表
color取色器值统一为 #rrggbb 小写十六进制；没有 alpha 通道
range拖动滑块只有近似值；要精确数字就用 number；常配 output 显示当前值
file选择文件配 accept 限定类型、配 multiple 允许一次选多个
hidden隐藏字段用户看不见但会随表单提交，常放编号；绝不能用来藏密码或敏感数据（看源码就能看见）

分组与校验：把表单管得清清楚楚

字段一多，表单就会变成一锅粥。两个元素能帮上大忙：

  • fieldset 是“一组字段”的框，legend 是这组字段的标题， 读屏软件会念出“报名信息，分组”；
  • 给 fieldset 写 disabled，组内所有控件一起禁用—— 比逐个写省事得多。

接下来是浏览器自带的约束校验（constraint validation）： 只要写了 required、pattern、min / max、 minlength / maxlength、正确的 type， 提交时浏览器就会先替你检查一遍，不合格就拦下并给出提示气泡——不写一行脚本。

三个与校验有关的开关，各有各的场合：

  • novalidate（写在 form 上）：整张表单关掉自带校验， 适合自己写一套提示；
  • formnovalidate（写在提交按钮上）：只对这一次提交跳过校验， “保存草稿”按钮的标准做法（例 4 的第二个按钮）；
  • :valid / :invalid（CSS 伪类）：按校验状态改样式， 例如给不合格的红框。注意一个坑：页面刚打开时，空的必填项就已经是 :invalid，一刀切地标红会让表单“一上来就满脸通红”； 更好的做法是配合脚本或新型的 :user-invalid（用户动过之后才算）。
心法：客户端校验是服务，不是防线

浏览器自带的校验只是帮用户少犯错：任何人打开开发者工具都能改掉它， 甚至绕过页面直接向接口发数据。所以真正的规则必须在服务端再校验一遍—— 前端校验负责体验，后端校验负责安全，两件事缺一不可。

本式小结

  • 单选靠同名互斥、靠 value 提交；复选组也用同名收集多个值；
  • select 配 option / optgroup， multiple 多选、size 定行数；datalist 是“可输入 + 给建议”；
  • textarea 的初始值写在标签之间；output 显示结果， progress / meter 表示进度与刻度；
  • 日期、时间、颜色、滑块、文件各有专用 type；file 需要 accept / multiple，上传时表单要写 enctype="multipart/form-data"；
  • hidden 字段能被用户看到源码，绝不能放敏感数据；
  • fieldset + legend 负责分组；自带校验靠 required / pattern / min / max 等，跳过校验用 novalidate 与 formnovalidate；
  • 服务端必须再校验一遍——前端校验是体验，不是安全。
练功 · 第八式
  1. 做一个“入派登记表”：门派（单选下拉，含空选项且必填）、想学的功课（三个复选）、 入门日期（type="date"，必填）、自我介绍（textarea，最多 200 字）。
  2. 给上一题加一个“用功时长”滑块（0–120 分钟，步长 15）， 并用 output 实时显示当前值。
  3. 思考：为什么浏览器的校验挡不住恶意提交？如果只靠它，会出现什么后果？
参考答案 1

检查点：select 的第一个选项 value=""（配 required 才能拦住“没选”）； 三个复选同名 drill 但 value 各不相同； textarea 的初始内容写在标签之间；fieldset + legend 成对出现。

参考答案 2

output 的 for 属性写它“是在算谁”的控件 id； 事件要监听 input（拖动过程中就触发）而不是 change （松手才触发）。

参考答案 3

因为校验发生在用户的浏览器里，而用户对自己的浏览器有完全控制权： 改属性、关脚本、甚至不用浏览器、直接给接口发请求（curl 之类的工具一行就能做到）。 只靠前端校验的后果很实际：僵尸程序可以提交空白数据、超长数据、 伪造的编号；如果服务端照单全收，轻则脏数据，重则绕开业务规则 （比如少填一个字段就绕过了本该收的费用）。 一句话：前端校验让好人少犯错，服务端校验让坏人做不了坏事。
