变量把值存起来，运算符则把值“用起来”： 加加减减、比大小、判断真假、给缺省值兜底。 这一式是 JavaScript 的算盘——算盘打错一格，后面全歪。

本式要点
  • 会用算术运算符，知道除法与取余在 JavaScript 里的特殊结果
  • 认清 + 的双重身份：既做加法也做字符串拼接
  • 比较一律用 ===，知道 == 会在哪里咬人
  • 掌握逻辑运算符的短路与返回值，会用 ?? 与 ?. 处理“可能没有”的值
  • 看得懂优先级与结合性，知道 ?? 为什么必须加括号

算术运算符

运算符 含义 例子 结果
+加1 + 23
-减5 - 8-3
*乘3 * 412
/除7 / 23.5（没有整除这回事）
%取余7 % 31；-7 % 3 得 -1（结果跟被除数同号）

++ / --自增 / 自减i++ 与 ++i都能让 i 加一，但“返回的值”不同（见下）

三个特殊结果必须认识，否则会以为程序疯了：

  • 1 / 0 → Infinity（正无穷）；-1 / 0 → -Infinity；
  • 0 / 0 → NaN（不是数字）；
  • NaN 参与的任何算术都还是 NaN——一旦某处算出 NaN，它会像墨滴一样染开， 所以看到 NaN 要往回找“第一个变 NaN 的地方”。

自增的两种写法差别在“返回值”： i++ 先给人旧值、再加一（后置）； ++i 先加一、再给新值（前置）。 写在自己的那一行（i++;）时两者没区别； 一旦嵌进别的表达式就会咬人——建议永远单独写一行。

复合赋值是“算完再存回去”的简写： x += 1 等于 x = x + 1， 同理还有 -=、*=、/=、%=、**=。 累加计数时最常用。

两个“看起来一样”的加号

+ 是 JavaScript 里唯一“身兼两职”的运算符： 两边都是数字时做加法，只要有一边是字符串就变成拼接。

两个与大小比较有关的怪脾气
  • null 与数字比大小时会被转成 0：于是 null > 0 为 false，而 null >= 0 为 true—— 看起来矛盾，其实只是转换规则不同（一个用数值比较，一个先转数字）； 结论：比较前先确认值不是 null/undefined；
  • NaN 与任何值比较都是 false： NaN < 1、NaN > 1、NaN === NaN 全是 false。

逻辑运算符：不只是真假

&&（并且）、||（或者）、!（取反） 的特别之处在于：它们返回的是“操作数本身”，而不是 true/false。 加上“短路”特性（结果已定就不再看后面），就长出了几种常用写法：

写法 怎么读 典型用途
a && b a 为假就用 a，否则用 b “条件成立才做”：isReady && start()
a || b a 为真就用 a，否则用 b 给默认值：name || "匿名"（注意 0、"" 也会被换掉）
!a 转成布尔再取反 判断“没有”：if (!list.length) { … }
!!a 取反两次，等于“转成布尔” 把任意值变成 true/false：!!"" 为 false

优先级、结合性与那个必须加括号的规定

表达式里谁先算，由优先级决定；同样优先级的，由结合性 （从左还是从右）决定。常用的顺序从高到低大致是：

层次 包含
最高分组 ( )、成员访问 . [ ]、可选链 ?.、new、函数调用
↓!、typeof、void、delete、++、--
↓**（右结合：2 ** 3 ** 2 ＝ 2 ** 9）
↓* / %，然后 + -
↓比较 < > <= >=，然后 === !==
↓&&，然后 ||，然后 ??
↓三元 ? :
↓赋值 = += …（右结合：a = b = 0 从右往左）
最低逗号 ,（在参数、数组里是分隔符，不是逗号运算符）

但真正要紧的不是背表，而是记住一条硬规定： ?? 不能和 &&、|| 直接混用，必须加括号—— 因为它们的优先级容易写错，语言干脆禁止你写模糊代码。

例 5 · 优先级现场（含那条“必须加括号”的规定）

    演示里用 new Function("…") 把那段有语法错误的代码“送进去编译”， 从而安全地把 SyntaxError 抓出来——因为语法错误在解析阶段就会中断脚本， 普通的 try…catch 是接不住的（第二十七式提过，第三十六式细讲）。

    心法：拿不准就加括号

    优先级表是给“读懂别人代码”用的，不是给自己炫技用的。 写的时候宁可多打两对括号：代码是给人读的，编译器不需要你省这两个字符。 一条实用的自查：把表达式念出来，如果需要停顿两秒才能说清先算哪一步，就该加括号了。

    本式小结

    • 算术：7 / 2 得 3.5；1 / 0 是 Infinity； 0 / 0 是 NaN，且 NaN 会“传染”；
    • + 双重身份：有字符串就拼接；想拼串请用模板字符串，想算数先转数字；
    • 比较一律 ===；== 会先转类型，只有 x == null 这个惯用法值得保留；
    • 逻辑运算符返回操作数本身并短路：&& 做“条件成立才执行”， || 做“兜底但会换掉 0 与空串”，!x / !!x 做真假转换；
    • ?? 只在 null/undefined 时兜底；?. 让“可能没有”的访问不再报错；
    • 速查表里的三元、展开、typeof、in、delete、位运算先混个脸熟，用到再回查；
    • 优先级与结合性：** 与赋值右结合，其余多为左结合；?? 不能与 &&/|| 直接混用，加括号即可；拿不准就加括号。

    参考答案 3

    因为这三者的优先级挨得很近、又没有直观的“常识”可依： a ?? b || c 到底是 (a ?? b) || c 还是 a ?? (b || c)， 不同语言的约定不一样，写的人与读的人极易理解错。 语言设计者干脆禁止这种模糊写法，逼你用括号把意图写出来—— 这与“宁可让代码啰嗦一点，也不要让人猜”的总体取向一致。 这也解释了本式的心法：拿不准就加括号，括号是最便宜的注释。
