骨架搭好了，该裁衣服了。CSS 这门手艺有个可爱的特点： 改一行，立刻看得见。这一式先不讲花哨的招式，只把“一条样式怎么生效”这件事说透。

本式要点
  • 看懂 CSS 的规则集：选择器、声明块、属性与值，以及注释的写法
  • 会用三种引入方式（外部、内部、行内），并知道它们的优先级关系
  • 写出第一批立刻见效的样式：颜色、字号、行高、背景
  • 会用浏览器开发者工具查看、临时修改、定位样式问题

CSS 长什么样

CSS（Cascading Style Sheets，层叠样式表）的语法只有一种“句型”：

四个名词先对上号，后面每一式都会用到：

名词 在上面的例子里 作用
选择器（selector） p “我要给谁化妆”——挑出页面上的哪些元素
声明块 { … } 一对花括号里的全部内容
声明（declaration） color: #b03a2e; 一条“属性：值”的交代，末尾的分号不能漏（最后一条可省，但建议都写）
属性 / 值 color / #b03a2e 要改哪一项，改成什么

三个容易踩的小坑，第一次写就该避开： 用中文标点（冒号、分号打成全角）会整条规则失效； // 不是 CSS 的注释（那是 JavaScript 的写法）； 花括号忘了成对，后面的样式会跟着一起崩。

三种引入方式

样式可以写在三个地方，效力与用途各不相同：

方式 写法 适合
外部样式表
（推荐）		 <link rel="stylesheet" href="style.css"> 写在 head 里 正式项目的首选：一份文件管全站，浏览器还能缓存
内部样式 <style>…</style> 写在 head 里 这一页专属的样式、教程演示、临时试验
行内样式 <p style="color: red"> 应急与脚本动态设置；写多了会很难维护
@import 在 CSS 里再引一份 CSS 不推荐：它会等主样式表下载之后再排队请求，拖慢首次显示

三者的关系可以用一句话记住：行内样式最“重”； 内部与外部样式之间，则看谁写在后面——同样“分量”的规则，后写的赢。 看一个现场实验：

例 1 · 行内样式盖过内部样式（谁在后面谁赢的前奏）

这一段由内部样式管：蓝色、加粗。

这一段又加了行内样式，于是它变成了朱砂色。

行内样式可以只改一部分：这次颜色变了，字重回到了正常。

这不是“行内天生更正确”，而是层叠规则里的一条：行内样式比外部、内部样式表更“重”。 第十五式会把整套比较规则摊开讲；现在只要知道它存在，并顺手养成习惯—— 正式样式写进样式表，行内只留给应急。

第一批能立刻见效的规则

有三类选择器先认识：元素选择器（按标签挑）、类选择器（按 class 挑）、 ID 选择器（按 id 挑，页面里只该出现一次）。它们的写法与用途：

写法 名字 挑中的是 例子
p { } 元素选择器 页面上所有 p 给全站正文定行高
.note { } 类选择器（前面一个点） 所有 class="note" 的元素 把一类提示文字变成灰底小字
#top { } ID 选择器（前面一个井号） id="top" 的那一个元素 页面头部这种“只此一处”的区域
例 2 · 三种选择器各挑各的

我是普通段落，只有浏览器的默认样式。

我带着 class="note"，所以有灰底与左边线。

我是 id="special" 的段落，被单独点了名。

注意演示里的选择器写成了 #css13-demo2 .note—— 这是一条后代选择器：意思是“在 #css13-demo2 这个范围里找 .note”。 教程的演示都要加这样的“范围前缀”，否则就会误伤页面上的其它元素； 放到你自己的项目里，写 .note { … } 就够用了。第十四式专讲选择器的各种组合。

开发者工具：CSS 的第二双眼

样式写多了必然要问“这条规则为什么没生效”。答案都在开发者工具里， 五步就能上手（Chrome / Edge / Firefox 操作基本一致）：

  1. 按 F12 或 Ctrl + Shift + I 打开开发者工具；
  2. 切到 Elements（元素）面板，点左上角的箭头图标，再去页面上点你想查的元素；
  3. 右侧 Styles（样式）面板从上往下列出所有命中的规则，被划掉的行就是被别的规则盖住了；
  4. 直接在上面改数值、加属性，页面会立刻变——这不会保存到文件，只是临时试验；
  5. 切到 Computed（计算样式），能看到“最终算出来”的值，长宽、颜色一目了然。
心法：先用工具找原因，再回去改文件

新手最常见的两种徒劳：一是“我明明写了却没生效”——其实被别的规则盖住了（Styles 面板里划掉那行）； 二是“为什么这么宽”——其实上一式留下的空白在撑场面（Computed 面板里看盒模型）。 在工具里改到满意，再抄回文件，比反复刷新猜十次都快。

山不让尘

山不让尘，故能成其高；川不辞盈，故能成其深。

把这句话抄在便签上，比抄十遍样式表更能撑住你练下去。

最后一行 margin-bottom: 0 值得留意：它写成了一个行内样式， 只是为了演示“临时改一处”的感觉。正式项目里请把这类微调也搬到样式表， 用一个类名解决（例如 .last { margin-bottom: 0 }）。

本式小结

  • CSS 的句型：选择器 { 属性: 值; }；注释用 /* … */，别用 //；
  • 三种引入方式：外部（推荐）、内部、行内；行内样式最“重”，样式表之间后写者赢，正式样式一律进样式表；
  • 三种基础选择器：元素 p、类 .note、ID #top；
  • 颜色、字号、行高、字体、背景、圆角，是最先见效的一批属性；
  • 开发者工具的 Styles 面板看“谁盖住了谁”，Computed 面板看“最终值”，改到满意再抄回文件。
练功 · 第十三式
  1. 给第十二式的个人主页建一份 style.css，用 link 引进去： 给 body 设一个字体、给段落设行高、给链接换颜色。
  2. 在同一页里加一段内部样式，把 h1 的字号改大； 再用开发者工具找到它，试着临时改成另一个值。
  3. 思考：既然行内样式的“分量”最重，为什么反而不推荐用它写正式样式？
参考答案 1

检查点：link 放在 head 里；href 的相对路径与 style.css 的位置对得上；保存后在开发者工具的 Network（网络）面板能看到它返回 200。

参考答案 2

在 Elements 面板选中 h1，右侧 Styles 里会出现 h1 { font-size: 2.4rem; }。 点数字即可改，页面上立刻变形；刷新页面，改动消失—— 这就是“工具里试验、文件里定稿”的工作方式。

参考答案 3

三个理由：其一，行内样式写在标签上，同一个样式要改十处就得改十次； 其二，它盖住了所有样式表里的规则，以后想统一改主题（比如换一套配色） 会发现怎么改都不生效，只能回头一个个删； 其三，它把“结构”和“外衣”又混在了一起，第十二式辛苦搭好的干净骨架被弄脏了。 结论：行内样式是应急工具，不是常规武器。
