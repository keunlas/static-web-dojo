标签各有各的本事，但有一批属性哪个标签都能写——它们叫全局属性。 这一式把它们串一遍，再翻到页面最上头那块从不露面的地方：head。

本式要点
  • 会用 id（唯一）与 class（可复用）给元素挂上钩子
  • 会用 data-* 存自定义数据，并知道脚本怎么读它
  • 认得 hidden、tabindex、contenteditable、title、lang 等属性的用途与坑
  • 能写出一份像样的 head：编码、视口、标题、描述、图标，以及脚本的 defer / async

全局属性一览

全局属性就是“写在任何开始标签里都合法、含义固定”的属性。常用的有这些：

属性 作用 注意
id 给这一个元素起全页唯一的名字 锚点跳转、label for、脚本查找都靠它；同一页不许重名
class 给元素贴分类标签，可以被很多元素共用 一个元素可以写多个类名，用空格分隔
data-* 存放自定义数据（data-author="墨白"） 标准属性不够用时用它，不要随手造新属性
style 行内样式 应急可以，正式样式请写进 CSS；行内样式很难被统一维护
title 补充说明，鼠标悬停时显示提示 触屏看不到、键盘用户也难触发；关键信息不要只放在这里
lang 声明内容的语言 <html lang="zh-CN"> 是整体声明，某段外文可单独写 lang="en"
dir 文字方向：ltr / rtl 阿拉伯语、希伯来语等从右往左书写的语言才需要
hidden 隐藏这个元素 布尔属性；与 CSS 的 display: none 视觉相同、语义不同
tabindex 控制键盘 Tab 顺序 0 加入自然顺序；负值可聚焦但不进 Tab 序列；尽量别用正数（会打乱全站顺序）
contenteditable 让元素内容可以直接编辑 真·就地编辑，适合做草稿板之类的工具
spellcheck 是否做拼写检查（"true" / "false"） 代码、专名多的输入框建议关掉
translate 是否允许浏览器翻译 translate="no" 保护品牌名与代码不被“译”得面目全非

三个钩子：id、class、data-*

这三者最常被混用，其实分工很清楚： id 是身份证（全页唯一，用来精确指向一个元素）； class 是标签纸（可以贴很多张，一批元素共用同一张）； data-* 是随身便签（存这条数据自己的信息，供脚本读取）。

tabindex="0" 的用处是让“本来不可聚焦”的东西（div、span） 也能被键盘走到。但请把它当成例外而不是习惯： 能用 button、a 这类天生可聚焦的元素，就不要用 div 加 tabindex—— 换标签能免掉一整套键盘处理（第十一式会把这个话题讲透）。

逐项拆开看：

写法 作用 要点
<meta charset="utf-8"> 声明文字编码 必须放在 head 最前面（前 1024 字节内），否则中文可能乱码
meta viewport 告诉手机按真实宽度渲染 响应式的第一块地基；本站每一页都有它
<title> 标签页标题、收藏夹名、搜索结果标题 每页都要有且各不相同；格式建议“本页主题 | 站点名”
meta name="description" 页面摘要 可能被搜索引擎用作结果下方的两行字；一页一句，写清“这页有什么”
meta name="robots" 给爬虫的指令 noindex 表示“别收录我”（工具页、临时页适合写它）
link rel="icon" 标签页小图标（favicon） 本站用内嵌 SVG，不产生额外请求
link rel="stylesheet" 引入样式表 放 head 里，页面不会“先素颜后上妆”（第十三式）
link rel="canonical" 声明这一页的规范网址 有多条路径指向同一内容时用；部署后填真实域名
script + defer / async 引入脚本，并控制执行时机 见下方解释

脚本的三种放法

脚本放哪里、加什么属性，决定了它什么时候执行：

写法 行为 适用
放在 </body> 之前 页面解析完才下载执行，最直观 新手首选；本站的 jQuery 篇演示就是这么放的
<script defer src="…"> 边解析边下载，解析完成后再按顺序执行 需要 DOM 就绪又不想拖慢页面的脚本；能保持先后顺序
<script async src="…"> 下载完立刻执行，不保证顺序 互不依赖的独立脚本（如统计代码）

还有一个新手常见疑问：为什么脚本放在 head 里却拿不到页面元素？ 因为那一刻 DOM 还没解析出来。defer 就是为这件事准备的开关； 本站则干脆用一行 loader 脚本 + 队列来解决（你查看本页源码就能看到）。

注意 og:image 必须是完整网址——抓取卡片的是对方的服务器， 它不知道你的相对路径从哪算起。静态站也可以把这些写死，只是换域名时要记得改。

心法：head 里的三条小纪律
  • charset 一定要靠前，别让浏览器猜编码；
  • 每页的 title 与 description 要各写各的，别复制粘贴；
  • 能被搜索到的页面再配 canonical 与 og:*， 工具页、临时页没必要。

本式小结

  • 全局属性哪个标签都能写；id 唯一、class 可复用、data-* 存自定义数据；
  • data-author 在脚本里读作 dataset.author；命名用全小写加连字符；
  • hidden 是语义上的“与内容无关”；contenteditable 让内容可编辑；
  • tabindex="0" 能让普通元素进入键盘序列，但优先选天生可聚焦的元素；
  • head 里必备：charset、viewport、title、description， 再加上图标与样式表；
  • 脚本三选一：body 末尾、defer（保序）、async（不保序）；
  • og:* 决定分享卡片，图片地址要写完整网址。
练功 · 第十式
  1. 给你的个人主页写一份完整的 head：编码、视口、标题、描述、图标、 样式表，再加一行 defer 的脚本。
  2. 做一个“工具箱卡片”：用 data-* 存下工具名与熟练度， 写一段脚本把两个值读出来显示在页面上。
  3. 思考：为什么网页里到处用 class，而 id 只在少数地方出现？ 如果全用 id 会有什么麻烦？
参考答案 1

检查点：charset 在最前；title 与 description 写的是这一页的内容； 样式表在 head 里；脚本带 defer 或放在 body 末尾。

参考答案 2

要点：data-* 里的值都是字符串；如果存的是数字， 参与计算前要自己转换（Number(tool.dataset.skill) 之类，JS 篇会讲）。

参考答案 3

因为两者的“唯一性”要求不同：id 必须全页唯一， 所以它只适合给“只此一个”的元素用（页头、页脚、主要区域）； 而按钮、卡片、列表项这类会重复出现的元素天生是“一批”， 只能靠 class 批量挂钩子。 全用 id 的第一个麻烦就是重名：一旦重复， label 会指向错误的输入框、锚点跳转失灵、脚本只拿到第一个匹配的元素—— 而且这类错误没有报错信息，只是“偶尔不对劲”，最难排查。
