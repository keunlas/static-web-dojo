骨架搭过、衣服穿过，这一页还差一味：会应答。 这一式不教新招式，只把前十五式攒下的本事用一遍—— 结构不动、样式不动，只加一个脚本，让它活起来。

本式要点
  • 学会先列“行为清单”，再决定每一件事该用哪个本事
  • 用 dataset + CSS 变量做主题切换，并用 localStorage 记住选择
  • 用 hidden 与事件委托做筛选、留言与删除
  • 用 scroll + 节流 + scrollTo 做“回到顶部”， 用 IntersectionObserver 做滚动高亮导航
  • 用一份验收清单给成品打分：能用键盘、关掉 JS 也不散、没有行内事件

成品先看

先看结果，再学过程。这一页的前两版都在，可以并排对比：

  • 第十二式的成品：纯 HTML 版（只有结构）；
  • 第二十六式的成品：穿上衣服版（加了 CSS）；
  • 第四十二式的成品：动起来版（本式新加的脚本）。

第三版的 HTML 与 CSS 与前两版几乎一字未改—— 只多了一个 <script>、几个 id 与 data-kind 之类的标记。这就是这一式最想让你看到的东西： 行为是叠加上去的，不是把结构推倒重来。

三件事各就各位：表单负责收集（HTML 校验先挡一道）、 脚本负责拦提交（preventDefault）、 存储负责记住。

四个要点：①新口信 unshift 进数组，最新的在最上面； ②每次改动后重新 renderMessages()，界面永远等于数据； ③删除用事件委托绑在列表上，按钮是渲染出来的也一样管用； ④dataset.index 存的是字符串，用之前 Number() 转回来。

第 4 步 · 回到顶部：跑得少的活儿，别每帧都干

按钮本身在 HTML 里带 hidden 属性（初始不显示），CSS 里一行 [hidden] { display: none !important; } 保证它真的藏起来。 behavior: "smooth" 是平滑滚动；如果读者在系统里选了“减少动态效果”， 别忘了用媒体查询把它和卡片动效一起关掉（第二十四式的规矩）。

第 5 步 · 滚动高亮：请观察者帮忙

自己监听滚动、算每个小节的位置，既啰嗦又容易算错。 现代浏览器里有个更省事的角色——IntersectionObserver （交叉观察者）：它替你盯着“某个元素有没有进入视野”，进了就叫你一声。

那个 rootMargin 的意思是“把视野缩小成屏幕正中间的一条窄缝”： 谁穿过这条缝，谁就是“当前这一节”。高亮之外还挂了 aria-current="true"，让读屏软件也能听出“你在这一节”。

收尾 · 把脚本放对地方

所有代码都写在 <body> 最后、</body> 之前： 脚本要操作的元素这时都已经在页面里了，不用等、也不用包一层“加载完成”的回调 （第二十七式讲时机时留下的习惯）。

对照验收清单

交付前逐条过一遍，每一条都能在浏览器里当场验证：

  • 关掉 JavaScript，页面依然可读：内容都在 HTML 里， 脚本只负责加行为——滚动高亮没了、留言板不能用了，但主页还站得住；
  • 所有操作都能用键盘完成：主题、筛选、提交、删除、回到顶部 全是真 <button>（第十一式）；
  • 用户输入一律走 textContent， HTML 里没有一处把用户输入拼进 innerHTML；
  • 没有行内事件：全页 onclick="…" 出现次数为 0， 监听都在脚本里 addEventListener；
  • 刷新之后该记住的还在：主题与口信； 浏览器禁止存储时给出提示而不是报错；
  • 两种打开方式都试一遍：直接双击（file://）与本地服务器 （http://）各走一遍五个行为，控制台不该有红字；
  • 动效照顾“减少动态效果”：prefers-reduced-motion 里关掉了卡片放大与平滑滚动。

本式小结

  • 综合修炼的顺序：先列行为清单 → 再逐条实现 → 最后逐条验收；
  • 换主题的诀窍是换变量（dataset 挂到 html 上 + 一套同名 CSS 变量），不要让 JS 去改每个元素的颜色；
  • 筛选用 dataset 存分类、用 hidden 显隐， 数据与样式各管各的；
  • 留言板三件套：preventDefault 拦提交、textContent 保安全、 localStorage 保记忆；
  • 高频事件配节流（回到顶部），复杂的观测交给 IntersectionObserver（导航高亮）；
  • 行为是叠加在结构与样式之上的：HTML 立骨架、CSS 裁外衣、 JavaScript 点灵魂，三样各归其位，页面就稳。

第一，颜色只写了一处：整套主题是十几个变量， 改一处变量，所有用到它的地方一起变；若用 JS 挨个改， 等于把 CSS 抄进 JS，以后每加一个元素都要记得补一行， 漏掉的地方就会在暗色下变成“黑底黑字”。 第二，职责分家：JS 只负责“现在是哪个主题”这一个状态 （挂在 html 的 data-theme 上）， 具体怎么变全是 CSS 的事——这也正是第十二式里“结构、样式、行为各归其位”的延续。 顺带还有第三个好处：以后想加第三套主题，只写一段 CSS，JS 一行都不用改。
