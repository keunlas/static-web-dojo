前面二十三式，页面都是“静”的。这一式给它加一点“呼吸”： 鼠标移上去轻轻浮起、按钮按下去有回应、加载时转个小圈。 动效是调味料——放对了提鲜，放多了齁人。

本式要点
  • 掌握 transition 四件套与常用缓动函数，知道哪些属性可以过渡
  • 会用 transform 做位移、缩放、旋转、倾斜，理解“多个变换的顺序”
  • 会用 @keyframes 写关键帧动画，掌握 animation 简写里各个值的含义
  • 记住两条底线：优先动画 transform 与 opacity、 必须照顾 prefers-reduced-motion

过渡 transition：从 A 到 B 的补间

过渡不创造新动作，它只做一件事：当某个属性变化时，别瞬间跳过去，而是用一段时间滑过去。 四个子属性拼成一套：

子属性 含义 常用值
transition-property对哪些属性做过渡具体的属性名，或 all（慎用）
transition-duration持续多久.2s、300ms
transition-timing-function用哪种节奏ease（默认）、linear、ease-out、cubic-bezier(…)、steps(…)
transition-delay延迟多久开始0s、.1s

简写 transition 的顺序是“属性 时长 缓动 延迟”—— 两个时间值里第一个是时长、第二个是延迟，这是最容易记混的地方：

还有一条常被忽略：不是所有属性都能过渡。 能过渡的是那些“值可以插值”的属性——颜色、长度、透明度、transform 等； 而 display、position 这类“开关式”的属性默认没有中间状态。

例 1 · 时长决定手感（三个按钮，只有时长不同）

把鼠标移到按钮上（或用 Tab 聚焦），体验三种手感——悬停不生效时，请用键盘聚焦试试。

时长没有绝对标准，但有几条经验：按钮反馈 0.1–0.2s、面板展开 0.2–0.3s、 大幅位移 0.3–0.5s；超过 0.6s 的动作会让人等得烦躁， 除非它本来就是“缓慢”的表达（比如淡入的封面图）。

缓动函数：动作的“性格”

取值 手感 适合
linear匀速，机械感进度条、旋转的加载圈
ease（默认）两头稍慢，综合平衡不确定用什么时的安全选择
ease-out开头快、结尾慢元素进场（浮出、滑入）
ease-in开头慢、结尾快元素离场（飞走、收回）
ease-in-out两头慢、中间快来回移动（抽屉、轮播）
cubic-bezier(x1,y1,x2,y2)自定义曲线“回弹”“超冲”这类个性动作
steps(4)一步一步跳逐帧动画、打字机效果

linear匀速
ease-in慢起快落
ease-out快起慢停

变形 transform：不动布局的“整形”

transform 是动画的最佳拍档，因为它不影响其他元素的排版—— 元素在文档流里的位置不变，只是“看起来”被挪动、放大、旋转了。

函数 作用 例子
translate(x, y)平移（可以写百分比：相对自身尺寸）translate(-50%, -50%) 配合 top/left: 50% 做居中
translateX / translateY只在一个方向平移悬停上浮：translateY(-4px)
scale(s)缩放，1 是原始大小图片悬停放大：scale(1.06)
rotate(deg / turn)旋转rotate(45deg)、rotate(.5turn)
skew(deg)倾斜做“速度感”的斜切文字
transform-origin变形围绕哪个点（默认正中心）transform-origin: left center：从左边开始放大
例 3 · transform 四兄弟（鼠标悬停或 Tab 聚焦）
上浮 translateY
放大 scale
旋转 rotate
倾斜 skewX
组合动作

组合写法里有个容易困惑的点：多个变换按从左到右的顺序生效。 translateY(-6px) scale(1.08) 是“先上浮再放大”， 而 scale(1.08) translateY(-6px) 是“先放大、再在被放大后的坐标系里往上挪”—— 后者的位移看起来会更远。顺序不同，结果不同。

提醒：transform 会创建新的层叠上下文

第二十式说过：transform 不是 none 的元素会自成一层。 所以给某个元素加了变形之后，它内部用 z-index 排的层级只会和“同层”的兄弟比较， 盖不住外面更靠上的元素——别再用 z-index: 9999 硬顶，先看看层叠上下文。

关键帧动画 @keyframes

过渡只能做“两点之间”的补间；要做“转一圈”“闪三下”这种多段动作， 就得用 @keyframes 定义关键帧，再用 animation 播放：

动画子属性 含义 常用值
animation-name用哪套关键帧自己起的名字
animation-duration一次播放多久.9s
animation-iteration-count播放几次数字，或 infinite
animation-direction方向normal、reverse、alternate（往返）
animation-fill-mode开始前/结束后停在哪个状态forwards（停在最后一帧，最常用）
animation-play-state暂停 / 继续paused（悬停时暂停很实用）
animation-delay延迟多久开始.2s（还能做“逐个出现”的错位效果）

新 左：animation: … linear infinite；右：关键帧写了 0% / 50% / 100%。

转圈用的 linear 是正确选择：旋转如果加上缓动，会一顿一顿的。 另外注意那个 role="status" 与 aria-label： 视觉上的“正在加载”，对读屏读者必须是文字上的说明—— 动效不能是唯一的信息渠道。

性能与体验的三条底线

底线 为什么 怎么做
优先动画 transform 与 opacity 这两个属性可以交给合成线程处理，通常不触发重新排版与重绘； 而动画 width/height/top/margin 每一帧都要重新算布局，长列表里会明显掉帧 “移动”用 translate 而不是改 left； “变大”用 scale 而不是改 width
照顾 prefers-reduced-motion 有前庭功能敏感的读者会被大幅动画晃得头晕；系统里那句设置是他们的求助信号 用媒体查询把动画关掉或缩短（例 5 的写法），至少保证不出现大幅位移
别让动效成为“唯一的信息” 色彩闪烁、图标抖动如果没配文字，色觉异常或读屏读者拿不到信息 配文字说明；闪烁类动画每秒不超过 3 次（避免诱发光敏性癫痫）
小技巧：用开发者工具看动画

打开 DevTools 的 Animations（动画）面板，触发一次动效， 就能看到时间轴、逐帧慢放、还可以把速度调成 10% 慢动作。 排查“为什么它动得怪”时，这个面板比反复刷新高效得多。

本式小结

  • transition 简写顺序是“属性 时长 缓动 延迟”，两个时间值里第一个是时长；
  • 能过渡的属性必须“值可插值”；display 这类开关式属性默认没有中间态；
  • 缓动决定性格：进场用 ease-out、离场用 ease-in、旋转用 linear、 逐帧用 steps()；
  • transform 不动布局，是动画的最佳拍档；多个变换按从左到右生效，顺序会影响结果；
  • transform 会创建层叠上下文（第二十式的坑在这里重逢）；
  • @keyframes 用百分比写多段动作，animation 简写里别忘了 duration 与 iteration-count；fill-mode: forwards 能停在最后一帧；
  • 三条底线：优先动 transform/opacity、照顾 prefers-reduced-motion、动效不承担唯一信息。
练功 · 第二十四式
  1. 给第十二式主页的“作品卡片”加悬停动效：上浮 4px、阴影加深， 时长 0.25 秒、缓动用 ease-out。
  2. 写一个“加载中”的小动画（转圈或三个点跳动）， 并配上 role="status" 与文字说明；再加媒体查询， 让“减少动态效果”的读者看到静止版本。
  3. 思考：同样是把一个盒子从左边移到右边，为什么推荐 transform: translateX()，而不是动画 left？

参考答案 3

因为 left 属于“布局属性”：它的每一帧变化都要让浏览器 重新计算布局（这个盒子动了，旁边的元素要不要跟着挪？）， 然后还要重新绘制，几十帧下来就很吃力； 而 transform 只是给这个元素换一个“绘制变换”， 不参与布局计算，很多情况下连重绘都能省掉，直接交给合成线程。 肉眼效果几乎一样，代价却差一个数量级——这就是“动画只动 transform 与 opacity”的由来。
