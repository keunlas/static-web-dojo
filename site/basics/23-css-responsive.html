同一个页面，要在六寸的手机和二十七寸的显示器上都好看—— 这件事没有“一招”，它是一套心法：从最小的屏幕写起，让布局自己会长， 实在长不好的地方，再用媒体查询扶一把。

本式要点
  • 理解“移动优先”：默认样式写给窄屏，用 min-width 逐级增强
  • 认准 <meta name="viewport">，知道少了它手机页面会变成什么样
  • 会写媒体查询（含范围语法）、知道断点该按“内容散架处”选
  • 会用四件武器：流式尺寸、弹性/网格、媒体查询、容器查询
  • 记住两条与无障碍相关的硬规矩：不禁缩放、触控目标别太小

先立规矩：viewport 与移动优先

每个页面 head 里那一行 viewport，是响应式的总开关：

  • 少了它，手机浏览器会假装自己有 980px 宽、再把整页缩小塞进屏幕—— 你以为的“适配好了”，其实只是被缩放了；
  • width=device-width 让布局视口等于设备宽度，媒体查询才有意义；
  • 不要写 user-scalable=no 或 maximum-scale=1： 那等于禁止低视力读者放大页面，是无障碍上的红线。

接着是写作顺序，也就是“移动优先”：

移动优先（推荐） 桌面优先（老写法）
默认样式 写给最窄的屏幕（单列） 写给最宽的屏幕（多列）
媒体查询 min-width 从小到大逐级增强 max-width 从大到小逐级降级
好处 小屏拿到最精简的代码；增强是“加”出来的，容易维护 小屏要不断覆盖大屏的样式，越写越乱

媒体查询：语法的全部家当

除宽度以外，媒体查询还能问浏览器很多问题，这几类最实用：

条件 含义 常见用途
orientation: landscape横屏 / 竖屏横屏时把工具栏变矮
prefers-color-scheme: dark系统是深色模式整套暗色配色（本站皮肤就用它）
prefers-reduced-motion: reduce用户要求减少动效关掉大幅动画（第二十四式）
pointer: coarse主指针是“粗的”（手指）把按钮做大一号
hover: hover设备支持悬停只在真有鼠标时才做悬停效果
print打印时去掉导航、展开链接地址

演示里那句 @media 写在样式表中段也没关系—— 媒体查询只看“条件是否成立”，不看它写在第几行。 但条件成立之后，里面的规则仍要按层叠规则参与竞争（第十五式）： 所以基础规则 .wide-only { display: none } 必须写在媒体查询 之前，否则同样权重下后写的会赢，标签永远显示不出来。 这个坑值得亲手试一次——把两段调换位置，就能看到“宽屏标签”彻底消失。

断点怎么选

新手最爱问“该用哪几个断点”。真正的答案是：先在浏览器里慢慢拉窄窗口， 看内容在哪个宽度开始别扭，那个宽度就是你的断点。 设备型号会过时，内容的“散架点”不会。几个常见的参考值：

参考断点 大致对应 常见调整
36em（576px）手机横屏 / 小平板卡片从单列变两列
48em（768px）平板竖屏导航从折叠变横排、侧栏出现
62em（992px）小笔记本三列布局、显示侧边栏
75em（1200px）桌面放宽正文最大宽度

单位建议用 em：在媒体查询里它相对浏览器的默认字号， 用户把默认字号调大时断点也会跟着变大，页面会提前切换到更宽松的版式； 而 px 断点对这类设置无动于衷。（页面缩放对两者都不影响。）

四件武器：不要只用媒体查询

武器 做什么 例子
① 流式尺寸 让尺寸自己跟着容器/视口伸缩，不用断点 width: 100%、max-width: 60rem、font-size: clamp(1rem, 2vw, 1.4rem)
② 弹性与网格 让布局自己换行、自己增减列 flex-wrap: wrap、repeat(auto-fit, minmax(220px, 1fr))
③ 媒体查询 结构要变（换位置、换顺序、显隐）时出手 @media (min-width: 62em) { … }
④ 容器查询 按组件自己的宽度适配（同一组件放进不同宽度的栏里都好看） @container (min-width: 30em) { … }（例 5）

顺序上有个经验：能用①和②解决的，就别写③。 媒体查询是重武器，写多了会变成“每个断点一套样式”，维护成本陡增。

三个具体场景的处理法

场景一：表格在窄屏撑破页面

手机上没有空间让五列表格舒展开。与其硬塞，不如给它一个可横向滚动的外壳： 页面不再被撑破，读者想看细节时自己滑一下。

可滚动区域要给键盘读者留门

一个横向滚动区，鼠标用户能拖、触屏用户能滑，但只用键盘的读者可能进不去。 给它加 tabindex="0" 与 role="region"、 aria-label="……（可横向滚动）"，键盘就能聚焦过去、再用方向键滚动 （第十一式）。本站的代码块就是这么处理的。

场景二：次要内容在窄屏怎么处理

三种做法，按推荐程度排序：重排 > 折叠 > 隐藏。 能用 Grid 换个位置解决的，就别折叠；能折叠的，就别直接 display: none—— 一旦隐藏，读屏软件与搜索引擎也一并看不到了。

场景三：触控目标别太小

手机上点不准，多半不是手抖，而是目标太小。无障碍标准的最低线是 24×24 CSS 像素（WCAG 2.2 AA），而各家设计规范普遍推荐 44×44 以上（Apple HIG 的 44pt、Material 的 48dp）。

容器查询：组件级的响应式

媒体查询问的是“整个窗口多宽”，可组件的烦恼常常是 “我所在的这一栏多宽”。容器查询正好补上这一环： 先给父元素声明“我是可查询的容器”，子元素再按容器宽度适配。

容器查询的好处很实在：同一个卡片组件，放进侧栏（窄）就是竖版， 放进正文（宽）就是横版，组件自己带适配能力， 不需要页面去为“它将来会被放在哪”操心。

怎么测：三步走

  1. 拖窗口：在浏览器里慢慢拉窄、拉宽，盯着每个断点附近有没有别扭的地方 （DevTools 的设备工具栏可以锁定常见手机宽度）；
  2. 换输入方式：只用键盘走一遍、只用触屏点一遍， 看看有没有“只能鼠标用”的交互；
  3. 上真机：模拟器再像也不是真机——尤其是在户外看屏幕、 用一只手操作、字号调到最大的时候。

本式小结

  • 响应式的起点是 viewport；永远不要禁用缩放；
  • 移动优先：默认样式给窄屏，用 min-width 逐级增强；
  • 媒体查询除了宽度，还能问方向、深色偏好、减少动效、指针粗细、打印；
  • 断点按“内容散架处”选，参考值 36/48/62/75em；单位用 em 更尊重用户的默认字号；
  • 四件武器：流式尺寸 → 弹性/网格 → 媒体查询 → 容器查询，能靠前解决就别用后面；
  • 窄屏表格用横向滚动外壳（记得给键盘留 tabindex="0"）； 次要内容优先重排、其次折叠、最后才隐藏；
  • 触控目标至少 24×24、推荐 44×44 以上；测的时候记得换输入方式、上真机。
练功 · 第二十三式
  1. 给第十二式的主页加一条媒体查询：窄屏单列、宽屏两列 （提示：用 Grid 改 grid-template-columns 最省事）。
  2. 把主页的大标题改成 clamp() 流体字号， 然后把窗口从最窄拉到最宽，确认它不超出上下限。
  3. 思考：为什么“把次要内容在窄屏直接 display: none”要慎用？ 请从两个不同的读者角度说明。
参考答案 1

也可以直接写 repeat(auto-fit, minmax(260px, 1fr))， 连媒体查询都省了——能靠布局自己解决的，就别写断点。 两种做法都值得亲手写一遍，体会差别。

参考答案 2

检查点：在 DevTools 里拖到 320px 宽，字号应当停在 1.6rem 附近不再缩小； 拉到 1600px 宽，应当停在 2.8rem 不再变大。 中间那段“1.1rem + 2.6vw”决定它跟视口增长的速度。

参考答案 3

第一类读者是用读屏软件或搜索引擎的人：display: none 的内容对它们同样不存在——你以为“小屏只是先藏起来”，对方却是彻底拿不到； 第二类读者是屏幕小但需求不少的人：比如用手机放大字号查看价格的用户， 被隐藏的运费说明、退换货政策恰恰是他最需要的信息。 更稳的做法是：装饰性的东西随便藏，信息性的内容用“重排（挪位置）” 或“折叠（<details>，需要时能展开）”来处理。
