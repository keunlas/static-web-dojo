跳到正文

前八式学的是零件，这一式开始把它们装成整机。 HTML 里有一批元素，默认长得和 div 一模一样，却在向机器宣告“我这一块是什么”—— 它们就是网页的地标。

本式要点
  • 说清语义化服务的是哪三类读者，明白“div 汤”的代价
  • 会用地标元素：header、nav、main、article、section、aside、footer
  • 掌握标题层级与分节的规矩：一个 h1、不跳级、分节要带标题
  • 会用 details / summary、time、address，并知道 div / span 什么时候该出场

为什么要语义化

先把话说透：把所有 div 换成 header、nav、main， 页面在肉眼看来一模一样。语义化不是给你看的，它服务三类“非视觉读者”：

  • 读屏软件：它能用快捷键在“地标”之间跳转。有地标，读者可以一句话跳到正文； 没有，就只能从头一个元素一个元素地听——那是几百次按键的差别；
  • 搜索引擎与聚合工具：它们靠标签判断哪段是正文、哪段是导航、哪段是页脚；
  • 后来的维护者（包括三个月后的你）：一眼看懂页面骨架，比对着满屏 div 猜结构强得多。

反面例子有个外号叫“div 汤”（div soup）：整页都是层层嵌套的 div， 类名起得再花，机器也不知道哪里是正文。语义化就是把这锅汤重新分装成几个标着名字的碗。

七个地标：页面骨架的零件

一张完整页面通常由这几个元素拼起来。表里的“数量”一栏格外重要—— 它们是出题人最爱考的细节：

元素 是什么 数量与位置
header 页头或某个区块的开头：站点标题、搜索、作者信息 可以有多个：页面级一个，article / section 内部还能各有一个
nav 主要导航链接的集合 可以有多个（如顶部导航 + 页内目录），但别给每一小撮链接都套 nav
main 这一页独一份的正文内容 整页只能有一个，且不能放进 header / nav / aside / footer / article 里
article 能独立成立的内容单元：一篇文章、一条评论、一张卡片 可以有多个；判断口诀：“把它单独拷到别处，还讲得通吗？”
section 一个带主题的分区 可以有多个；通常要有标题，没有合适标题就说明该用 div
aside 与主内容间接相关的内容：侧栏、延伸阅读、小贴士 可以有多个；它不应该抢正文的位置
footer 页脚或某个区块的结尾：版权、联系方式、相关链接 与 header 同理，可以有多层

    标题层级与分节

    地标解决“大块怎么分”，标题解决“里面怎么走”。三条规矩请记牢：

    • 一个 h1：说清这一页是什么（本站的 h1 由页头统一注入）；
    • 层级不跳级：h2 下面是 h3，别从 h2 蹦到 h4；
    • 分节要带标题：用了 section / article，里面的第一个标题就是它的名字。

    本站每一式右侧的“本式目录”，就是照着正文里的 h2 / h3 自动生成的—— 标题写得好不好，读者一按目录就知道。

    这段结构里藏着一个常被问的问题：article 和 section 怎么选？ 口袋里的判断法有三步：能独立成立（像一篇文章、一条评论）用 article； 只是文章里的一个主题段落，用 section 加标题； 两者都不像（纯粹为了排版方便）就用 div。 它们可以互相嵌套——例 2 就是 article 里装了两个 section。

    div 与 span：无语义的万能容器

    讲了半天语义，可别把 div 和 span 当成“错误标签”。 它们是没有语义的容器，专门留给“只想分组、没有合适语义”的场合：

    元素 显示方式 什么时候用
    div 块级（自占一行） 给一组元素打包、配样式或供脚本操作，且找不到更贴切的语义元素时
    span 行内（跟着文字走） 只给句子里的几个字加样式或挂 id、data 属性时

    判断顺序建议倒过来想：先问“这块到底是什么”，再找对应元素；都对不上，才用 div。 本站页面里就有这样的例子：正文之外那层负责布局的容器是 div class="content"—— 它只是排版的脚手架，没有语义，用 div 正合适。

    本式小结

    • 语义化服务读屏软件、搜索引擎与维护者；一堆 div 堆出来的页面叫“div 汤”；
    • 地标七件套：header / nav / main / article / section / aside / footer， 其中 main 每页只能有一个，且不能嵌在别的地标里；
    • 一个 h1、层级不跳级、section 要有标题；
    • details + summary 是零脚本折叠面板；dialog 要脚本才能模态弹出；
    • time 让时间机器可读；address 只用于作者联系方式；
    • div / span 是无语义容器：先找语义，找不到才用它。
    练功 · 第九式
    1. 为你的个人主页画骨架：写出 header、nav、main、 aside、footer 五个地标，每个里放一两行占位文字。
    2. 在 main 里写一篇 article：要有 header（标题 + time）、 两个带标题的 section、以及一个带 details 的 footer。
    3. 思考：把 main 换成 div，页面看起来毫无变化。 那到底谁会因此受损？请具体说出一种使用场景。
    参考答案 1

    检查点：h1 只有一个；nav 里是一个链接列表（用 ul，第三式说过）； main 是 body 的直接子元素，没被塞进别的地标里。

    参考答案 2

    检查点：article 内可以有自己的 header / footer； 两个 section 都带标题；details 放在 footer 里也完全合法 （它只是“把细节折叠起来”，与位置无关）。

    参考答案 3

    受损的是靠键盘与读屏软件浏览的人。具体场景： 一位读屏软件用户打开你的页面，只想直接读正文。 如果页面有 main，他可以按一下“跳到主内容”的快捷键，一步到正文； 如果那里是 div，读屏软件不会把它当地标，他就只能从页头开始， 把品牌名、十几个导航链接、搜索框、侧栏……一个一个听过去—— 每换一个页面都要重听一遍。这就是为什么语义化被称作“网页的无障碍地基”。
