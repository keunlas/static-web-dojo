程序的力量来自两件事：会分岔与会重复。 分岔让代码能根据情况走不同的路，重复让我们不必把手写的十遍改成一百遍。 这一式就是这两件事的全部家当。

本式要点
  • 会用 if / else if / else 处理范围与复杂条件，避开 = 与 === 的坑
  • 会用 switch 处理“等值判断”，并知道漏写 break 会发生什么
  • 分得清 while、do…while、for 各自适合什么场景
  • 说得出 for…of 与 for…in 的区别，知道遍历数组与对象各该用什么
  • 会用 break 与 continue 控制循环的“提前结束”与“跳过这一轮”

分岔：if 与 switch

if 是最常用的分支：括号里的东西会按第二十八式的真假值规则转成真假。 条件从具体到宽泛地排，第一个成立的生效：

两个新手必踩的坑，提前钉住：

  • 别把 === 写成 =：if (x = 1) 不是判断， 而是“把 1 赋给 x，然后判断 1 是不是真”——它永远为真（而且很多编辑器会提醒你）；
  • 大括号别省：if (ok) doA(); doB(); 里的 doB() 其实不在 if 里。省一对花括号，后患无穷。

当判断的都是“某个值等于哪一项”时，switch 比一串 else if 更清楚。它有两个要点： 比较用的是严格相等（===）， 以及每个 case 末尾要写 break：

漏写 break 时，代码会继续往下执行下一个 case 的内容， 这叫“贯穿”（fallthrough）。有时我们故意这么写（上面把周六周日并在一起）， 但多数时候它是 bug 的来源——例 2 会把两种情形都演出来。

      小心无限循环

      如果循环条件永远为真，页面就会卡死（浏览器会弹“页面无响应”）。 排查口诀：把循环体里“让条件变化”的那一句找出来—— i++ 忘了写、或者写在了 if 里面，是最常见的两种。 在开发者工具里试代码时也要留神：卡死时只能关标签页。

      遍历：for…of 与 for…in

      这两个名字只差一个词，用途完全不同，是新手最容易混的一对：

      for…of for…in
      给你什么 值（数组里的元素、字符串里的字符） 键（对象的属性名；数组则是字符串下标）
      适合 数组、字符串、Map、Set、NodeList 对象（但更推荐 Object.keys/values/entries）
      注意 拿不到下标；需要下标就用 entries() 或经典 for 会把继承来的可枚举属性也翻出来；不要拿它遍历数组
      例 4 · 同一个数组，两种遍历；再看对象该怎么遍历

        一句话记法：of 要值，in 要键。 数组用 for…of（或 forEach/map，第三十二式）， 对象用 Object.keys/values/entries——它们只翻“自己的”属性，不会把继承来的也带上。 演示里那句 for (const [i, fruit] of …) 用到了一点“解构”—— 把每一对 [下标, 值] 直接拆成两个变量，第三十二式会专门讲它， 现在照着读成“第 i 项是 fruit”即可。

        提前收工：break 与 continue

        关键字 作用 例子
        break 立刻结束整个循环（或 switch） 列表里找到目标就停，不必再往后看
        continue 跳过本轮剩下的代码，直接进入下一轮 遇到空白项就跳过，不参与统计
        标签 outer: 跳出外层循环（嵌套循环时用） 少用；能用函数提前 return 就别用标签
        例 5 · break 与 continue 的现场

          这两个关键字没有“风格好坏”，只有“该不该用”： 已经找到答案就别再找（break 往往还能省下大量循环）， 这一轮不满足条件就别往下算（continue 能少写一层 if）。

          该用哪一个：速查表

          场景 首选 理由
          按范围 / 多个条件分支if / else if / else条件可以任意写
          按“某个值等于哪一项”分支switch比一串 else if 更整齐
          简单的二选一三元 ? :一行写完，但别嵌套太深
          已知次数或需要下标for三段式一眼看清边界
          次数不定、只知道何时停while条件即出口
          至少要跑一次do…while判断在末尾
          遍历数组 / 字符串 / Map / Setfor…of直接拿值，也不怕下标写错
          遍历对象属性Object.keys/values/entries只取自己的属性，还可以配合 map / filter
          预告一个经典坑：循环里的 var 与 let

          用 var 在循环里创建函数（比如给每个按钮绑事件）， 它们最后都会看到同一个“最后的 i”——因为 var 是函数作用域。 把 var 换成 let，每轮都会得到自己的 i，问题自然消失。 背后的原理是闭包与作用域，第三十一式会把这段讲透。

          本式小结

          • if 条件从具体排到宽泛；别把 === 写成 =，别省大括号；
          • switch 用于等值判断，用严格相等比较；break 漏写会贯穿， 有时故意（合并多个 case），多数时候是 bug；default 兜底；
          • 三种循环：已知次数用 for、次数不定用 while、 至少执行一次用 do…while；记得让条件最终会变假，否则页面卡死；
          • for…of 拿值（数组、字符串、Map、Set）， for…in 拿键（数组上是字符串下标，不推荐）；对象遍历优先 Object.keys/values/entries；
          • break 结束整个循环、continue 跳过本轮；标签能跳出多层，但少用；
          • 循环里创建函数时，用 let 而不是 var（第三十一式详解）。

          参考答案 3

          因为 for…in 遍历的是“可枚举的属性”， 其中包含从原型链继承来的属性。 如果某个库给 Object.prototype 加过一个可枚举的方法 （老代码里真的发生过），for…in 就会把它也翻出来， 你的循环里突然多出一个莫名其妙的键。 Object.keys(obj) 只返回“自己的、可枚举的”属性名， 行为稳定、还能接着用 map / filter 等数组方法处理。 如果确实要用 for…in，记得前面加一句 if (!Object.hasOwn(obj, key)) continue; 过滤。
