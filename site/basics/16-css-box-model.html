跳到正文

在 CSS 眼里，页面上没有“文字”和“图片”，只有一个个盒子。 这一式就把盒子拆开看：它有几层、每层多厚、盒子之间为什么有时会“粘”在一起。 明白了这些，你就能回答那句经典疑问——“为什么它比我以为的宽”。

本式要点
  • 认清盒子的四层：内容、内边距、边框、外边距
  • 分清 content-box 与 border-box，并知道为什么项目里常用后者
  • 会用 padding / margin 简写，理解百分比与负值、auto 的用法
  • 看懂外边距折叠、会用 overflow 处理溢出，知道行内元素为什么“不听话”

每个元素都是一个盒子

元素的盒子由内到外分四层，用一件包裹来打比方最清楚：

层 CSS 属性 打比方 要点
内容 width / height 包裹里的东西本身 文字、图片等实际内容所占的区域
内边距 padding 包裹里的泡沫纸 内容与边框之间的空隙，有背景色
边框 border 包裹的纸箱壳 有厚度、有颜色、有样式（第十九式细讲）
外边距 margin 包裹之间留的距离 透明，不属于盒子本身，只负责推开邻居
例 1 · 四层盒子的样子（每一层都标了颜色）
我是一个盒子：浅色渐变是外边距的位置（透明），粗虚线是边框，虚线以内是内边距，中间白底才是内容。

一句话记住分工：padding 是盒子自己的“肉”，margin 是盒子与邻居的“距离”。 所以给按钮加 padding 会让按钮变大，加 margin 只会把它推离旁边的东西。

width 量的是哪一层：box-sizing

这是盒模型里最容易出错的一处：width: 200px 到底量的是哪一段？ 答案取决于 box-sizing：

取值 width 的含义 实际占位公式
content-box（默认） 只算内容区 width + padding×2 + border×2
border-box（推荐） 把内边距与边框算进去 就是 width（内容区 = width − padding − border）
例 2 · 同样写 width: 200px，实际占位却不一样（脚本量给你看）
content-box：width 只管内容区
border-box：width 已经把四周算进去

padding 与 margin 的写法

两者写法完全一样，从一条到四条，按顺时针顺序取值：

写法 含义
padding: 10px四边都是 10
padding: 10px 20px上下 10，左右 20
padding: 10px 20px 30px上 10，左右 20，下 30
padding: 10px 20px 30px 40px上、右、下、左（顺时针）
padding-top、margin-inline 等单独指定；inline 指书写方向上的“左右”

三个容易踩的点：

  • 百分比怎么算：padding 与 margin 的百分比 都以“包含块的宽度”为基准——包括上下方向！所以 padding-top: 50% 得到的是一段竖着的高度，常被用来做固定比例占位；
  • 负 margin 合法：能让元素向左上“拉”，一些经典布局用它做边缘对齐， 但也会让元素互相压住，使用时务必在窄屏下检查；
  • margin: 0 auto：给定了宽度的块级元素，水平方向会居中—— 这是最省事的水平居中法（竖向的 auto 一律算 0）。

外边距折叠：为什么它们“粘”在一起

相邻的竖直外边距会合并成一个，取较大的那个，而不是相加。 这个现象叫外边距折叠（margin collapsing），共三种典型情况：

  1. 兄弟之间：上面盒子的下边距与下面盒子的上边距合并；
  2. 父子之间：父元素没有上边框 / 上内边距 / 内容时， 子元素的上边距会“跑”到父元素外面去（看起来父元素也被推下去了）；
  3. 空盒子：一个没有内容、没有 padding/border 的块，自己的上下边距合并成一个。
例 3 · 三种折叠现场（脚本量出真实间距）
兄弟 A：下边距 30px
兄弟 B：上边距 10px —— 两者不叠加，取大的那个
父子折叠：我的上边距跑到了父元素外面
同样的结构，给父元素加 overflow: hidden 后就不再折叠

正在测量……

折叠只发生在块级元素竖直方向之间，下面这些情况都不折叠： 水平方向、行内块、浮动元素、绝对定位元素、以及 flex / grid 容器里的子项。 想阻止父子折叠，最常用的三招是给父元素加 padding、border， 或者让它成为一个独立的格式化上下文（例如 overflow: hidden、display: flow-root）。

心法：别跟折叠较劲，理解它就行

折叠不是 bug，而是排版传统（印刷时代段落之间的间距就是合并的）。 排版正文时它让间距均匀好看；需要精确控制间距时， 优先用 padding 或容器 + gap，而不是一串 margin （第二十一、二十二式会看到 gap 有多省心）。

溢出：内容装不下怎么办

给盒子定死了宽高，内容却更多时，就发生溢出。 overflow 决定怎么办：

取值 行为 常见用途
visible（默认）照样画出来，哪怕超出盒子保持原样；可能出现重叠
hidden超出部分裁掉，不出现滚动条清理浮动、做圆角裁切；内容会被真的切掉
scroll总是显示滚动条需要固定滚动区域时
auto需要时才出现滚动条最常用：可滚动的列表、代码块
clip裁掉且不允许任何滚动纯粹的视觉裁切

还能分方向：overflow-x: auto; overflow-y: hidden （横向可滚、纵向裁切）——宽表格在小屏上常这么处理。

例 4 · 同一段文字，四种 overflow 处理方式
visible日拱一卒，功不唐捐。山不让尘，川不辞盈。这一段会溢出到盒子外面。
hidden日拱一卒，功不唐捐。山不让尘，川不辞盈。这一段被裁掉了。
scroll日拱一卒，功不唐捐。山不让尘，川不辞盈。这一段可以滚动查看。
auto日拱一卒，功不唐捐。山不让尘，川不辞盈。这一段需要时才出滚动条。

行内元素的“不听话”

前面讲的宽高、上下边距，对行内元素（display: inline，如 span、a、strong）并不完全适用，这是新手最常撞的墙：

属性 块级（block） 行内（inline） 行内块（inline-block）
width / height生效无效（由内容决定）生效
水平 margin / padding生效生效生效
竖直 margin生效不生效生效
竖直 padding / 边框撑开盒子画出来，但不撑开行高（可能压住上下行）撑开
排列方式独占一行跟着文字排跟文字排，但内部当盒子处理
例 5 · 三种显示方式对比（注意竖直边距有没有生效）
block：宽高与上下边距都生效 inline：宽高与上下边距不生效，底色只跟着文字走 inline-block：盒子属性生效，但仍跟文字排在一行

实际写页面时的经验：想让一个元素“自带盒子行为”又不想独占一行， 用 inline-block（标签、按钮、小卡片）； 但在现在的项目里，更常见的做法是用 display: flex 排一行， 让每个孩子天然成为“有盒子属性的块”（第二十一式）。

补一句细节：行内块元素的竖直边距确实会生效， 只是在行内排版里它还要和“基线对齐”一起算，位置常常比你预想的更靠上或更靠下。 所以真要整整齐齐排一行元素时，用 flex 加 gap 才是省心且不易出错的做法。

本式小结

  • 盒子四层：内容、padding（有底色）、border、margin（透明、只推邻居）；
  • 默认 content-box：width 只算内容区；常用 border-box 让宽度所见即所得；
  • 简写按顺时针：上 → 右 → 下 → 左；百分比以包含块宽度为基准（含上下方向）；
  • margin: 0 auto 水平居中；负 margin 能用但要小心压盖；
  • 竖直方向的外边距会折叠（兄弟取大者、父子会“外溢”），flex/grid 子项与行内块不折叠；
  • overflow：auto 最常用，hidden 会真裁掉内容；
  • 行内元素的宽高与竖直 margin 不生效，inline-block 是折中方案。
练功 · 第十六式

三种做法的取舍：直接加到一个方向上最简单，但下次有人再改另一个方向又会踩坑； 用 gap 则完全绕开折叠——这也是现代布局推荐 flex/grid 的原因之一。

参考答案 3

是同一个机制：overflow: hidden 让这个元素成为一块独立的格式化上下文 （BFC，block formatting context）。在这个“独立王国”里： ① 子元素的外边距不再和父元素的外边距合并（父子折叠被切断）； ② 浮动子元素会被父元素的高度计算包含进去（父元素不再“塌陷”）， 所以看起来就像把浮动包住了。同一套机制还顺带让元素避开旁边浮动的影响。 现代写法更愿意用 display: flow-root 来做这件事——它专门为“我要一个干净的 BFC”而生， 副作用比 overflow: hidden 小（不会裁掉内容）。
