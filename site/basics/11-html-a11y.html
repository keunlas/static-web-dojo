跳到正文

写页面的终极标准只有一条：谁来都能用。 用键盘的人、用读屏软件的人、在刺眼阳光下看手机的人、手腕打着石膏的人—— 这一式讲的不是“给别人做的慈善”，而是把你自己将来也会遇到的处境提前照顾好。

本式要点
  • 知道无障碍服务哪些人，理解“语义优先”为什么是第一条规矩
  • 会给图标按钮、图片这类“没有文字的东西”起名字（alt / aria-label）
  • 能让页面被键盘完整走通：Tab 顺序、可见焦点、跳转链接
  • 会用 aria-describedby、role="status" 这类工具做友好的表单提示，并知道 ARIA 的三条戒律
  • 掌握一份能自己动手跑的自测清单（键盘、缩放、对比度、动画）

无障碍是给谁做的

很多人以为无障碍（accessibility，常缩写为 a11y）是为“少数人”做的额外工作。 把清单摊开看，你会发现它照顾的是所有人一生中都会路过的状态：

  • 暂时受伤：手腕骨折、刚做完眼科手术、抱着一岁孩子只能用一只手；
  • 环境限制：地铁上没信号、工地旁边太吵、正午阳光直射屏幕；
  • 设备限制：老人机屏幕小、用了八年的旧电脑、鼠标滚轮坏了；
  • 长期状态：低视力、色觉异常、全盲、听障、阅读障碍、手部震颤。

马路上的“缘石坡道”本来是给轮椅修的，结果推婴儿车的人、拉行李箱的人、 骑滑板的人都受益——这种效应被称为“坡道效应”。 网页无障碍是同一种东西：你为少数人做的改善，最后惠及所有人。

第一条规矩：语义优先

第九式讲了语义化让机器看懂结构，这里说它的实战价值： 用对元素，键盘行为、读屏语义、焦点管理都是免费送的； 用 div 假装按钮，就得自己补齐这一整套，而且极容易漏。

例 1 · 假按钮与真按钮（试试用 Tab 键分别走到它们，再按回车）

假按钮（用 span 装的）： 装成按钮的 span ——Tab 走不到它，回车也按不动。

真按钮： ——Tab 能聚焦，回车、空格都能触发。

触发记录：假按钮 0 次（只能鼠标点），真按钮 0 次。

想让那个 span 也支持键盘，你得补上 tabindex="0"、 role="button"、keydown 里判断回车与空格、再自己画一个焦点样式—— 写了三十行，还未必比浏览器原生行为更稳。 所以第一句话永远是：能用原生元素，就别自己造。

给“没有文字的东西”起名字

屏幕上的东西，视觉读者一眼就懂；但一个只有放大镜图标的按钮， 读屏软件念出来可能只是一句“按钮”。这时要用属性补上可访问名称：

场景 写法 说明
图片 alt="…" 第四式讲过：内容图写描述、装饰图写 alt=""
图标按钮 <button aria-label="搜索"> 按钮里没有文字，就用 aria-label 给它一个名字
装饰性图标 <i class="bi bi-star" aria-hidden="true"> 让它从朗读里消失，别念出一串图标名
图标后本来就有文字 <a href="…"><i aria-hidden="true"></i>回到首页</a> 文字已经说明了用途，图标只需要闭嘴
例 2 · 三个图标按钮：一个没名字，两个有好名字

点上面的按钮，看看脚本能读出什么名字。

第一个按钮在视觉上“有图标”，在朗读里却是一片空白；第二个按钮多了一个 aria-label，读屏软件会念“搜索，按钮”；第三个按钮用可见文字说明用途， 图标设成 aria-hidden="true"，读出来是“去藏经阁，链接（按钮）”。 能写可见文字就别用 aria-label——文字对所有人都可见，标签只对机器可见。

让键盘走遍全站

键盘用户浏览页面的方式和你用鼠标很像：Tab 前进、Shift + Tab 后退、 Enter 确认、Space 勾选、Esc 关闭浮层。要做到三件事：

  • 能走到：所有可操作元素都在 Tab 序列里（原生元素天生就在，别用正数 tabindex 打乱顺序）；
  • 看得见：焦点在哪要一目了然。永远不要写 outline: none 却不给替代样式——那是把键盘用户的眼睛蒙上；
  • 跳得过去：页面开头放一个“跳到正文”的链接，让人跳过几十个导航项。 本站每个章节页都有，平时看不见，按第一下 Tab 就会现身——现在就可以试试。

另外两条与键盘相关的小规矩：用 :focus-visible 而不是 :focus 给“键盘聚焦”单独设样式（鼠标点击时不闪一圈）；弹层打开后把焦点移进去、关闭后还给触发它的按钮 （jQuery 篇与 Bootstrap 篇的组件会替你处理大部分）。

表单提示与动态消息

表单是无障碍最容易失守的地方。三条基本功： 每个控件都有 label（第七式）； 相关的说明用 aria-describedby 挂上去， 让读屏软件念完名字接着念说明； 动态消息交给 role="status" / aria-live="polite"， 这样“订阅成功”这类提示会被自动播报，而不必让人重新找一遍。

校验失败时的提示也要说清“哪一格、错在哪、怎么改”，并且别只用颜色： 红色边框之外，再给一句文字说明——色觉异常的读者看不见“只是变红了”。

ARIA 入门与三条戒律

ARIA（Accessible Rich Internet Applications）是一组补充属性， 用来描述那些原生 HTML 表达不了的状态与角色。常用的先认这几个：

属性 作用 例子
role 声明“这是个什么东西” role="status"、role="dialog"、role="navigation"
aria-label 给元素起一个朗读用的名字 图标按钮、只有图形的链接
aria-labelledby 用页面上某段已有文字当名字 对话框标题：aria-labelledby="dialog-title"
aria-describedby 补充说明（比名字更细） 输入框后面的提示文字（例 3）
aria-hidden="true" 让装饰性内容从朗读里消失 纯装饰图标；绝不能盖住可聚焦元素
aria-expanded 说明“展开 / 收起”状态 手风琴按钮：aria-expanded="false"
aria-live / role="status" 内容变化时自动播报 提交结果、搜索命中数量

三条戒律，记住能少踩坑：

  1. 能用原生就别用 ARIA：<button> 好过 <div role="button">——后者不会白得键盘行为；
  2. 不要用 ARIA 撒谎：给 div 写 role="button" 却不处理键盘，等于给读屏用户画了一张假地图；
  3. aria-hidden="true" 不能盖住可聚焦的东西： 键盘能走到、读屏却念不出，是最让人困惑的状态。

颜色、动画与自测清单

还有两类问题不在“结构”里，却同样挡住人：

  • 对比度：正文与背景的对比度至少要 4.5:1，大字号与图标至少 3:1。 常见的失败是把浅灰字放在白底上——“设计感”有了，眼睛却读不动；
  • 动画：有前庭反应的人会被大幅动画晃晕。 用 CSS 动画时要照顾 prefers-reduced-motion，让系统里选择“减少动态效果”的人 看到静态版本（第二十四式会实际写出来）。
心法：无障碍五问自测清单
  1. 只用键盘能不能做完全部操作（Tab 走一遍，看焦点是否可见）；
  2. 把页面放大到 200%，内容有没有被切掉、有没有横向滚动；
  3. 关掉图片（或用开发者工具看），alt 写对了吗；
  4. 把屏幕调成灰度，还看得出哪些是错误、哪些是重点吗；
  5. 检查所有按钮与链接的名字：读出来是一句人话，还是“按钮”“链接”？

本式小结

  • 无障碍服务所有人：语义优先、原生优先，能少写代码还更稳；
  • 给“没有文字的东西”起名字：图片用 alt、图标按钮用 aria-label、 装饰图标用 aria-hidden="true"；
  • 键盘三件事：走得到、看得见焦点、能跳过导航（.skip-link）；
  • 表单三件套：label、aria-describedby、role="status"；
  • ARIA 三条戒律：能用原生就别 ARIA、别撒谎、aria-hidden 别盖住可聚焦元素；
  • 对比度 4.5:1（大字号 3:1），动画要照顾 prefers-reduced-motion；
  • 收尾前过一遍「五问自测清单」——它比任何工具都快。
练功 · 第十一式
  1. 找一页你自己写的页面，只用键盘走一遍：把走不通的地方列出来，逐个修好。
  2. 做一张“工具条”：三个图标按钮（搜索、收藏、分享），每个都要有正确的名字， 并在页面上写一句注释说明为什么这样写。
  3. 思考：为什么“给 div 加 role="button"”不如直接换成 <button>？ 用键盘与读屏软件两种视角各说一条理由。
参考答案 1

常见的三处失守与改法： ① 用 div 当按钮 → 换成 button； ② 给 *:focus { outline: none } 却没补替代样式 → 改用 :focus-visible 画一个看得见的轮廓； ③ 页面开头没有跳转链接 → 加 <a class="skip-link" href="#main">跳到正文</a>， 并给 main 写上对应的 id。

参考答案 2

检查点：每个按钮都能被 Tab 走到（button 天生可聚焦）； aria-label 说明用途；图标都写了 aria-hidden="true"。

参考答案 3

键盘视角：button 自带“可聚焦 + 回车/空格触发”的完整行为， 而 div role="button" 只是对读屏软件“声称”自己是按钮， 键盘仍然走不到它，必须自己补 tabindex 与键盘事件，还容易漏掉空格键。 读屏视角：原生按钮会连同禁用、按下、展开等状态一起播报， 这些都是浏览器与辅助技术约定好的“通用语”；手写的 role 一旦状态没同步， 读屏用户听到的就是过时甚至错误的信息。
