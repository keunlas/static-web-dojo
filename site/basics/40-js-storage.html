前面三十九式，我们都在操心“页面里”的事。这一式往外看一圈： 窗口有多大、人在哪一页、来过几次——浏览器早把这些藏在一排现成的对象里， 顺手还能在本地存点东西，关了页面也不丢。

本式要点
  • 会用 window 读视口尺寸与滚动位置，知道它同时是全局对象
  • 会用 location 读当前地址、改 hash，并监听 hashchange
  • 会用 localStorage 存取字符串与对象（JSON.stringify / parse）
  • 分得清 localStorage 与 sessionStorage，知道存的是本机、不上传
  • 说得清 file:// 下为什么 fetch 读不了本地文件，以及静态站点该怎么带数据

window：浏览器递给你的总管家

window 是页面里的“全局对象”：你在顶层写的 var、 声明的函数，最后都挂在它名下（所以 window.setTimeout 与直接写 setTimeout 是一回事）。它还负责报告浏览器窗口的状态：

问它什么 回答
window.innerWidth / innerHeight视口（内容区）的宽高，像素
window.scrollY / scrollX已经向下 / 向右滚了多少
window.devicePixelRatio屏幕像素比（高分屏常见 2，打印设计稿时会用到）
window.localStorage本地仓库（本式后半段的主角）
window.scrollTo(x, y)滚到指定位置（第三式的锚点跳转就是它的功劳）
心法

浏览器不是只给你一块画布，而是给了你一整套屋子：窗口、地址、历史、仓库。 先知道屋里有什么，遇事才不至于自己造轮子。

例 1 · 窗口有多大、滚到哪了（拖动窗口或滚页面再点一次）

    location 与它的邻居们

    想知道“我现在在哪一页”，问 location；想带着读者走， 改它的属性就等于导航——location.href = "…" 会跳转， location.reload() 会刷新。常用的一族对象先认个门：

    对象 管什么 常用
    window全局对象、视口与滚动innerWidth、scrollY、scrollTo()
    document页面本身（第三十七式）querySelector()、title
    location当前地址href、protocol、hash、reload()
    history前进 / 后退back()、pushState()
    navigator浏览器与系统信息language、onLine、userAgent
    localStorage本地仓库（下面细说）getItem()、setItem()

    地址里那个 # 后面的部分叫 hash（锚点）。 改 hash 不会让页面重新加载，却会留下历史记录、还能触发 hashchange 事件——早年的“单页应用”就是靠它做路由的， 现在做“页内小导航”依然好用。

    例 2 · 读地址、改 hash、听 hashchange

      上面表格里还留着一位没细说的邻居：history。 它管的是浏览器那对前进 / 后退按钮与地址栏的历史记录—— 除了 history.back() / history.forward()， 现代还有一个 history.pushState(状态, 标题, 地址)： 它能在不刷新页面的前提下，把地址栏换成另一个地址并留下一条历史记录 （点后退还能回来）。这本来是为“无刷新改地址”准备的：

      本站为什么只用 hash、不用 pushState

      在 file:// 下打开本站时，pushState 换“真实路径”的那一条 会被浏览器直接拒绝——实际报的是 SecurityError：本地文件的来源是 null， 不允许凭空造出一个 file:///… 地址（实测于 Chromium： history.pushState({}, "", "/tmp") 抛错， 而换成 "#dummy" 这样的锚点就正常）。 所以本站的页内跳转一律走 hash（# 那一段）—— 它不涉及服务器，刷新也不会坏。 等你把站点放到真实服务器上，pushState 就是“无刷新改地址”的正经工具： 它的第一参数是状态对象（不能是函数），会在 popstate 事件里原样还给你。

      本地仓库：localStorage 与 sessionStorage

      刷新一下页面，JavaScript 里的变量就全没了；想让一小块数据留下来 （主题偏好、草稿、练习进度），就用浏览器给的本地仓库。 它只存在这台电脑的这个浏览器里，不会自动上传， 也不该拿来存密码、身份证号这类敏感信息。

        双击打开时会撞上的那道坎

        本站的铁律是“双击即开”，而浏览器出于安全考虑 不允许 file:// 页面用 fetch / XHR 读本地文件 （否则任何一个网页都能偷看你硬盘里的东西）。这时想读数据，有两个办法： 起一个本地服务器（python3 -m http.server，第九式那样）， 或者把数据写成 JS 文件，用 <script src> 引进来—— 脚本自古可以跨源加载，本站的全站搜索索引就是这么存的。

        本式小结

        • window 是全局对象，也报告视口与滚动：innerWidth、 scrollY、scrollTo()；
        • location 管地址：href 跳转、hash 是锚点、 hashchange 能听出锚点变了；
        • localStorage 存字符串、留到下次打开；sessionStorage 只活到关标签页；对象要先 JSON.stringify；
        • 本地仓库只在这台电脑、这个浏览器里，涉及隐私的数据别往里放；
        • file:// 下 fetch 读不了本地文件：要么起本地服务器， 要么把数据写成 JS 用 <script src> 引进来；
        • 键名加项目前缀（如 dojo40-notes），别用 data 这种谁都会用的名字，免得和别处的存储打架。
        练功 · 第四十式
        1. 做一个“主题开关”：一个复选框控制页面变深色，用 localStorage 记住选择，刷新后仍然生效 （提示：把值存成 "dark" / "light" 两个字符串之一）。
        2. 做一个“页内小导航”：三个按钮分别把 location.hash 改成 #one / #two / #three， 并监听 hashchange，在页面上写出“现在停在 #几”。
        3. 思考：为什么 fetch 在 file:// 下读不了本地 JSON， 而 <script src="…"> 可以？这给“纯静态站点怎么带数据” 什么启示？
        参考答案 1

        三点值得留意：①键名带项目前缀，避免与别的存储撞车； ②打开页面时先读一次并应用，否则“记住了”等于没记； ③读写都走同一个 apply 函数，界面与存储不会各说各话。 （本站顶栏的明暗切换就是这套路数。）

        参考答案 2

        改 hash 不会让页面重新加载，却会留下历史记录—— 所以浏览器的“后退”键能回到上一个锚点，这也是它能当路由用的原因。 若要让浏览器跳到对应位置，页面上还得有一个 id 与它同名 （第三式的锚点链接）。

        参考答案 3

        fetch 受同源策略约束：页面只能向“同一个源”要数据。 file:// 页面没有像样的源（不同机器、不同目录都算不同源）， 浏览器干脆一律拦下它对本地文件的读取——这是为了防止网页偷看你的硬盘。 <script src> 则是浏览器自古放行的“跨源通道”（脚本、 图片、样式表都算），所以把它当数据通道用是可行的： 数据文件里写一句 window.MY_DATA = […]，页面里就能直接用。 启示：纯静态站点要带数据，可以把数据嵌进 JS（本站的搜索索引 assets/js/search-index.js 就是这么生成的）； 一旦数据要“按需获取、可能变动”，那就该交给服务器了—— 这也是下一式要聊的边界。
