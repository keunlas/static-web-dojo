跳到正文

HTML 十式学完，该交一份答卷了。这一式不教新标签，只做一件事： 用最纯粹的 HTML，手写一个像样的个人主页—— 一行 CSS 都不加，因为骨架没搭好，穿什么衣服都撑不起来。

本式要点
  • 把前十式的零件拼成一页完整作品，知道每个元素“为什么在这一格”
  • 用六步拆解法从骨架写到页脚，每一步都能单独验收
  • 用一份自检清单给作品打分，找出自己的盲区

为什么故意不打扮

如果一开始就套上漂亮的 CSS，你看到的是“样式撑起来的效果”， 甚至会为了视觉硬把结构掰歪。这一版就是让结构光着身子接受检查： 标题层级对不对？地标齐不齐？表单能不能用键盘填完？ 等第二十六式，我们再回来给它裁衣服——那时你会发现，好骨架配衣服很省力。

自检清单

写完别急着满意——拿这张清单逐条过一遍。它比“看起来还能看”可靠得多：

  • 一个 h1，层级从 h1 → h2 → h3 逐级向下，没有跳级；
  • 地标齐全：header、nav、main、aside、footer， 其中 main 只有一个；
  • 每个 section 都有标题，每个 article 都能独立成立；
  • 表单：每个控件都有 label（for 与 id 对得上），必填项写了 required；
  • 链接：文字能独立成句（不写“点这里”），锚点目标真实存在；
  • 图片：有 alt、有宽高，配合 figure / figcaption；
  • 键盘：只用 Tab 与回车能不能走完全页，焦点是否看得见；
  • 脱掉样式还讲得通：把所有 CSS 去掉，页面的阅读顺序依然自然。

本式小结

  • 综合修炼的做法：先看成品，再按“骨架 → 页头 → 正文 → 卡片 → 联系 → 侧栏页脚”六步组装；
  • 每一步都能单独验收：head 齐不齐、section 有没有标题、label 对不对；
  • 结构先行的好处：这一页一行 CSS 都没有，却已经能被读屏、键盘与搜索引擎正常使用；
  • 好骨架是后面所有样式与脚本的地基——第二十六式会回来给它打扮。
练功 · 第十二式
  1. 照着六步，写出属于你自己的个人主页（内容换成你的真实信息，别照抄墨白）。
  2. 给页面加一个“本页目录”：在正文开头放一个 nav， 列出各节的锚点链接，并确认每一跳都落对地方。
  3. 思考：如果把 article 全部换成 div，页面看起来毫无变化。 对读屏软件的读者来说，损失了什么？
参考答案 1

没有唯一答案，用上面的自检清单逐条核对即可。三个最容易失手的地方： ① 为了好看硬把 h3 当小号 h2 用（层级会乱）； ② 导航里的锚点 #works 拼错一个字母，点了没反应； ③ 表单只写了 placeholder 却没写 label。

参考答案 2

要点：nav 配一个 aria-label 说明这是哪一组导航 （页面里有两个以上导航时，这个名字能让读屏软件把它们区分开）； 锚点目标就是各 section 的 id。

参考答案 3

损失的是“这是一篇独立内容”的宣告。读屏软件有一组快捷键按文章跳转， 用户听到“文章，站桩三月记”就知道这里开始是一篇完整内容， 可以用快捷键一篇一篇往下跳；换成 div 之后，这些快捷键全部失效， 读者只能从头到尾一格一格听——在日志越来越长的页面上，这个差别会越来越大。
