一个网站里，同一个朱砂色会写几十遍；换一次配色，就得全局搜索替换几十处。 CSS 变量就是为这件事准备的：把会重复的值收进一个名字里，改一处，全站生效。 这一式讲它，也顺便把“主题切换”这件事做完。

本式要点
  • 会声明 --name: 值、用 var(--name) 取值，理解它“参与继承与层叠”
  • 会用作用域做局部覆盖：同一个组件在不同位置长成不同的样子
  • 会写回退值 var(--x, 兜底)，并知道“值非法”时会发生什么
  • 能自己搭一套主题变量并切换（本站的明暗模式就是这么做的）
  • 知道变量与 calc()、JS 的配合方式，以及它会踩的几个坑

自定义属性：声明与取值

它的正式名字叫自定义属性（custom property），写法是“-- 开头的属性名”：

三个和预处理器（Sass/Less）“变量”不同的地方，值得先分清：

特点 说明
浏览器原生支持 不需要编译，写完就能用；还能在开发者工具里实时改
参与层叠与继承 谁都能读子孙节点的变量；在某个元素上重新定义，就只影响它和它的子孙
值可以是“一串东西” 不只是颜色和长度，整段值都能装： --shadow-card: 0 2px 6px rgb(0 0 0 / 12%)、 --font-title: italic 700 1.5rem/1.3 "Songti SC", serif

命名上有两条硬规矩：必须以 -- 开头（这是它区别于普通属性的标志）， 而且区分大小写（--Color 与 --color 是两个变量）。 习惯上用全小写加连字符：--brand-color、--space-md。

作用域：在哪儿定义，就管哪儿

这是 CSS 变量最好用的一点：它天生会继承。 在 :root 上定义是“全站默认”，在某个元素上定义就是“这个元素的子树换一套值”。

坑：回退值救不了“值写错了”

回退值只在变量不存在时生效。 如果变量存在、但替换进去之后整条声明非法（比如把一段颜色塞给 padding）， 浏览器不会退回那个兜底值，而是把这条声明当作 unset 处理—— 结果往往是“什么都没发生”，比报错更难查。所以变量的值要和使用它的属性对得上号。

例 3 · 三种情况：有变量、没变量用兜底、值非法
① --tone 已定义：文字是绿色。
② --not-defined 没定义：于是用了兜底的朱砂色。
③ --tone 定义了、但值不是颜色：这条声明直接作废，兜底也不会生效——所以这行是默认墨色。

主题切换：把所有颜色收进一处分

有了变量，换肤这件事就变成了“换一组变量值”。 最经典的写法是：把变量定义在 :root，再用一个属性选择器整组覆盖。

本站的明暗模式就是这套做法（选择器换成 Bootstrap 约定的 html[data-bs-theme="dark"]，好处是 Bootstrap 自己的组件也跟着换）。

几个值得知道的进阶点

  • 变量不能当属性名或选择器用：var(--prop): red 是无效的， 选择器里也不能写 var()；
  • 可以用 @property 给变量“上户口”（较新的能力）： 声明它的类型、初始值与是否继承，浏览器就能对它做校验甚至动画：
  • 命名建议：按用途而不是颜色值命名——写 --color-link 比 --red 耐用，换配色时不用改名字；
  • 别把什么都做成变量：用一次的值直接写就行； 值得抽出来的是“会重复出现”“以后可能要统一调整”的那些。

本式小结

  • 声明用 --name: 值，取值用 var(--name)；必须以 -- 开头，区分大小写；
  • 它参与层叠与继承：:root 上是全站默认，写在某个元素上就只管它的子树；
  • 回退值 var(--x, 兜底) 只在变量不存在时生效； 变量存在但值非法时，整条声明作废（unset），不会退回兜底；
  • 主题切换＝换一组变量：[data-theme="dark"] { --bg: …; }， 本站的明暗模式正是这套做法；
  • 变量可以放进 calc()、repeat() 等函数，也可以在媒体查询里换值， 但不能用在媒体查询的条件里；
  • JS 用 setProperty() 改变量，是“状态集中管理”的常用搭配；
  • @property 能给变量声明类型与初始值，这类变量才能参与动画。

参考答案 1

检查点：把 <html data-theme="dark"> 手动改一下， 整页应该立刻换色；如果某个地方没变，说明那里还写着写死的颜色值。

参考答案 2

这正是“局部变量”的用法：组件内部不去猜调用者想要什么颜色， 只提供一个变量口子；调用者在自己那一行里给它赋值即可。

参考答案 3

因为回退值的判断发生在“变量能不能取到”这一步， 而“值合不合法”要等到替换进属性之后才知道。 规范的处理是：替换后若整条声明非法，就把这条声明当作 unset 丢掉—— 这比“悄悄退回兜底值”更可预测： 否则一个拼错的变量名会静默地套用另一套颜色，问题会被藏起来， 开发者反而更难发现“我写的变量根本没生效”。 让错误显现出来，通常比替用户兜住更有价值。
