跳到正文

招式练熟了，接下来讲究“省力”。网页跑得快不快，往往不取决于你用了多高级的写法， 而取决于你有没有少做无用功——这一式，我们说说那些一次养成、长期受益的习惯。

本式要点
  • 需要反复用的选择结果，先存进变量，别每次重查
  • 查找“由大变小”：给 ID 就查 ID，能限定范围就限定范围
  • DOM 操作凑成一批再动手：先拼好，再一次插入
  • 动态内容用事件委托，避免逐个绑定，也避免“新元素没绑上”
  • 能用原生一行解决的问题，不必绕道 jQuery

心法一：少找——缓存选择器

每次写 $('.item')，浏览器都要在整篇文档里翻找一遍。找一次不算贵， 可要是在循环里、在每次点击里反复找，账就慢慢大了。习惯写法是：查一次、 存进变量、反复用。变量名前面加个 $ 是社区惯例，一眼看出“这是个 jQuery 对象”。

心法二：找得准——限定范围

选择器越具体，浏览器越省力。优先级大致是： $('#id')（最快，内部走原生的取 ID）→ $('#scope').find('.item')（先框定范围，再在里面找）→ $('div.list ul li span.active')（层层筛选，最慢）。

给 $() 传第二个参数，就是“在谁里面找”： $('.item', $scope) 等价于 $scope.find('.item')， 但写法上更清楚地告诉你“这是局部查找”。下面两块场地里都放着同名的小桩， 看范围一限定，结果就分得清清楚楚：

心法三：少改 DOM——凑成一批再动手

改 DOM 是网页里最贵的动作之一：每动一次，浏览器都可能要重新计算布局。 往列表里加 100 条数据，逐条 append 就是 100 次改动； 先用字符串或数组拼好、再一次 append，改动只剩一次。

    心法四：事件用委托，写法用原生

    • 事件委托：动态增删的元素，直接绑定会漏、会重复绑； 委托到父级一次性解决（第五式已详述）。这既是正确性问题，也是性能问题；
    • 改类代替改样式：连续设置多个 css() 不如切换一个类， 样式交给 CSS，浏览器更容易优化；
    • 能用原生就原生：element.id 比 $(el).attr('id') 直接；str.trim() 比绕道工具函数省事； Array.prototype.forEach 也能替下简单的 $.each；
    • 先 detach 再操作：要对一大块已有内容动手时， 先 .detach() 摘下来、改完再放回去，比在页面里改更省重排。
    客观地说：别过早优化

    这些心法用在小页面上，收益可能只有几毫秒，肉眼看不出来。先写得清楚， 再在卡顿出现的地方动手——本式的价值在于“养成习惯”， 而不是让你从此不敢在循环里写选择器。真正会拖慢页面的，通常是几千次 DOM 操作、 几百万次循环，而不是一句 $('.item')。

    练功 · 第十四式
    1. 把例 3 的逐条插入改成“先造好数组、一次 append”，再用计时按钮对比前后差别。
    2. 把一段“每次点击都重新 $('.card')”的代码改成缓存写法（用变量存起来）。
    3. 思考题：事件委托为什么既是性能优化、又是正确性问题？什么情况下反而不该用委托？
    参考答案 1

    数组 + join('') 与直接拼字符串效果相近，但数组写法在要过滤、 要格式化时更灵活。要点始终是：DOM 只碰一次。

    参考答案 2

    注意前提：这份缓存对应的是“当时存在的那些卡片”。如果卡片会动态增删， 要么在增删之后同步更新缓存（$cards = $('.card')）， 要么改用事件委托、把操作交给父级处理。缓存不是一劳永逸，而是“知道它何时会过期”。

    参考答案 3

    性能层面：委托只在父级绑一个处理函数，而不是给每个子元素都绑一份； 正确性层面：后来动态加进来的元素根本没有机会“被绑”，直接绑定必然漏。 但委托也有不该用的场合：如果事件的本意就是“限制在某些特定元素上”， 委托到父级反而要反复判断来源；如果父级之外还有一层会拦截事件（比如某些组件的 内部处理），委托也可能失灵。判断标准还是那句： 看这批元素是会变，还是永远不变。

    本式小结

    • 反复用的选择结果先缓存；选择器写得越具体越省力，优先 ID、限定范围；
    • DOM 操作凑批：先拼好、再一次插入；数据来自用户输入时用 .text() 造节点；
    • 动态内容用事件委托；样式变化优先切类；简单的事交给原生方法；
    • 先写清楚、再优化——优化的目标是让页面流畅，不是让代码难读；
    • 忘了某个方法在哪一式学的？藏经阁的 jQuery 方法速查按类别列好了全部方法。
