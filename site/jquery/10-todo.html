十式剑诀学到最后一式，规矩不是再学新招，而是把学过的招式连成一套。 本式就用 jQuery 配上 Bootstrap，从零手写一个待办清单——它小到一口气能读完， 却把本回大半的心法全用上了：选择器、事件、增删改、类切换，外加一位新朋友 localStorage。 写完你会发现：江湖上多数页面，翻来覆去不过这几招。

本式要点
  • 用 Bootstrap 搭出待办清单的三块骨架：输入组、列表组、统计栏
  • 复习取值、判空、创建节点、入列的完整增删改链路
  • 用事件委托让“新加的任务”天然可切换、可删除（呼应第五式）
  • 用 localStorage 存 JSON，刷新不丢，file:// 直接打开也照常

结构：先立骨架

写页面像盖房子，先立结构。一个待办清单就三块：输入区（写新任务）、 列表区（放任务）、统计栏（记账）。输入区用 Bootstrap 的 input-group 把输入框和按钮粘成一组（第二回第八式）； 列表区用 list-group（第二回第七式）。 先看静态骨架——

添加：让任务进列表

骨架立好，上行为。点“添加”要做三件事：取值、判空、入列。取值用 .val()（第三式）；判空前先 .trim() 去掉首尾空白——注意，jQuery 4 已经删掉了 $.trim， 直接用 JavaScript 原生的字符串 trim()；入列用 $('<li>') 创建新节点、再 .appendTo() 挂进列表（第八式）。

两个细节：任务文字交给 .text() 而不是 .html()——用户输入当纯文本处理， 绝不解释成标签；再给输入框绑一个回车事件，体验翻倍。

例 2 · 点击按钮或按回车，任务入列

    试试空着点“添加”——输入框会红一下脸。

    心法：创建即配置

    jQuery 允许一行把节点造出来并配好：$('<li>').addClass(…).append(…).appendTo(…)。 链式调用从头到尾不落地，新节点出生时就已经穿戴整齐。

    完成与删除：让任务活起来

    任务加进来了，还得能“做完”和“作废”。点任务本体，用 toggleClass() 切换 done 类（第四式），划线变灰交给两个 Bootstrap 工具类一起切换。点 ✕ 则删除所在任务——这里必须用事件委托 （第五式）：把监听绑在永远存在的 ul 上， 选择器指向 .btn-del，于是每个新加的任务出生自带删除能力。

    还有一个隐蔽的坑：点 ✕ 时，事件会一路冒泡到 li，把完成状态也顺手切了。 所以 li 的处理器先问一句——点的是删除按钮吗？是就让路。

    统计与清空：给列表一本账

    统计栏是列表的账本，任何一次改动后都要重新记账。把 updateStats() 抽成一个函数： 总数 $('… li').length、已完成 $('… li.done').length——选择器的 隐式遍历（第二式）在这里自动数人头。添加、切换、删除之后各调它一次。 “清空已完成”不过是选中 li.done 全部 remove()。 没有已完成时顺手禁用按钮——布尔状态一律用 .prop('disabled', …)。

    持久化：刷新不丢

    最后一块拼图是 localStorage：浏览器自带的键值仓库，只存字符串，容量约 5MB。 存的时候用 JSON.stringify() 把任务数组压成字符串，读的时候用 JSON.parse() 还原——这是 JavaScript 原生本领，与 jQuery 各司其职。 规矩很简单：任何一次数据变动后都调 save()， 页面启动时调一次 load()。

    它不依赖服务器：file:// 直接双击打开同样可用——数据存在本机浏览器里， 离线照常。不同浏览器对本地文件的存储分区略有差异，但本页的存读不受影响。

      3. 思考题：删除按钮为什么用事件委托？在每次创建任务时给按钮逐个绑定 .on('click', …)，行不行？
      参考答案 1

      按钮就放在“清除已完成”旁边（btn btn-sm btn-outline-primary）。 addClass() 会自动对选中的每个 li 都加类——隐式遍历的老朋友； 已经完成的项再加一次也无妨。别忘了 updateStats() 和 save()， 不然数字和存档都会漏账。

      参考答案 2

      maxlength="20" 一行挡住打字超长，但粘贴、程序赋值仍能绕过，所以 JS 侧用 slice(0, 20) 再兜底。排序的妙处是：append() 对已在页面里的节点 是“移动”而不是“复制”——把数组按新顺序 append 回去，任务就在原列表里排好了队。

      参考答案 3

      逐个绑定不是不行——创建时对每个按钮 .on('click', …)，按钮同样会生效。 但委托更稳，理由有三：其一，规则集中一处，以后增删任务不必记得同步补绑定，漏一个就失灵一个； 其二，本例的任务项 li 本身也是动态的，“点击切换”若直接绑在 li 上， 同样要逐个绑，而委托一次绑定就管住了现在与将来的所有项；其三，委托把“会发生什么”写在 ul 上，代码读起来像在列表门口立了块告示牌，行为和容器一起走。 最不推荐的是在创建时写 onclick="…" 属性——行为与结构耦合，还容易重复触发。

      本式小结

      • 结构先行：Bootstrap 管样子（input-group / list-group），jQuery 管行为；
      • 增删改一条链：val() 取值 → trim() 判空 → $('<li>') 创建 → append 入列；
      • 类即状态：done 类既管样式又管统计，一处改动、处处刷新；
      • 事件委托让动态内容天然可交互，新任务出生即带删除能力；
      • localStorage + JSON 让数据跨刷新存活，离线照常。
