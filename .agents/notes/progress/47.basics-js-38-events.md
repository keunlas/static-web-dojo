## 本批完成的事

**`site/basics/38-js-events.html` 事件**（6 个演示 + 3 道练功 + 3 个结构块）：

- **事件驱动的思路**：把「页面一加载就把活干完」与「等用户动作再干活」对照，给出三步写法
  （找元素 → `addEventListener` 绑回调 → 其余交给浏览器），点明回调和第三十一式的血缘；
  随后是事件对象九行速查表（`type` / `target` / `currentTarget` / `clientX·Y` / `key` / `code` /
  `timeStamp` / `eventPhase` / `preventDefault` / `stopPropagation`），并配
  **「this、currentTarget 与箭头函数的坑」警示框**（普通函数的 `this` 就是绑监听器的元素，
  箭头函数没有自己的 `this`；要拿元素就用 `currentTarget`）；
- **绑事件与解绑事件**：`{ once: true }` / `{ capture: true }` 两个常用选项；
  「解绑必须传同一个函数引用」；解释 `element.onclick = fn` 与 HTML 里的 `onclick="…"`
  这两种马甲「只能挂一个」，本教程统一用 `addEventListener`；
  **例 1**：按两次「绑一个新监听器」后点「+1」，**四行日志只加 1**
  （同一个 `d1Tick` 重复绑只生效一次）；解绑一个后再点不再加；
  `{ once: true }` 的按钮响应一次后自己禁用，再点也不加行；
- **事件对象**：**例 2** 把 `target`（真正被点的）与 `currentTarget`（正在听的）放进同一次点击：
  点按钮时先听见按钮上的箭头函数（实测 `this === currentTarget → false`），
  再听见卡片上的普通函数（`→ true`，且 `target` 是按钮、`currentTarget` 是卡片）；
  点卡片里的文字时 `target` 变成那个 `p`；卡片还挂了 `keydown`（`tabindex="0"`），
  读出 `event.key` 与 `event.code`；示例末尾「例 2 的两条结论」把这两条规矩收口；
- **事件流：冒泡、捕获与事件委托**：结构块画出一次点击的完整旅程
  （document → html → body → 外层 → 目标 → 一路回流），说明默认监听器跑在冒泡阶段、
  `eventPhase` 会如实告知所处阶段；点明委托的原理与两个好处（挂一个管一片、新元素不用重绑）；
  **例 3**：一次点击依次打印
  `外层：捕获(1) → 内层：捕获(1) → 目标：冒泡(2) → 目标：捕获(2) → 内层：冒泡(3) →
  外层：冒泡(3) → document：冒泡(3)`；勾上「内层拦住：stopPropagation」再跑，
  冒泡到内层就断、外层收不到，**而捕获阶段照旧**；正文顺带区分
  `stopPropagation` / `stopImmediatePropagation` / `preventDefault` 三者分工；
- **默认行为与取消**：**例 4** 一个开关管三件事——链接跳转、输入框写入字符、表单提交刷新；
  正文强调「拦表单提交要拦 `<form>` 的 `submit`，不是按钮的 `click`」，并给出
  `submit` + `FormData` + `Object.fromEntries` 的写法骨架，补一句
  「`preventDefault()` 只对可取消事件有效（看 `event.cancelable`）」；
- **事件委托**：**例 5**：列表预置两条待办、每条带删除按钮；新增一条后
  **它的删除按钮没绑任何监听器，照样能删**（委托监听器用
  `event.target.closest(".d-todo-del")` 认领，再用 `closest("li")` 找到所属条目）；
  另设「旧办法：给每个按钮逐个绑」的对照按钮，说明真正的代价是
  「每来一条新条目都得补绑、漏了就失灵」；配「委托的三个注意点」警示框
  （不冒泡的事件要换成 `focusin` / `mouseover` 等、要用 `closest` 而不是直接信 `event.target`、
  回调开头先守卫）；
- **高频事件：防抖与节流**：先给两个函数的骨架（防抖用 `clearTimeout` + `setTimeout`，
  节流用 `Date.now()` 记上次放行时间），点明两者都靠第三十一式的**闭包**记住定时器与时间戳；
  **例 6** 三栏对照计数（原样 / 防抖 / 节流，间隔 400ms）：连点 5 次即时读数为 `5 / 0 / 1`，
  等 700ms 后变成 `5 / 1 / 1`——防抖「停手后才跑一次」、节流「每段最多一次」当场可见；
  输入框那条路同样生效，「清零重来」把三栏归零；
- **本式小结**六条 + 练功三题（待办清单用 `submit` 与委托、自己写一份 search 防抖、
  思考题：为什么 `stopPropagation` 拦不住捕获阶段的监听器）+ 三份参考答案
  （含「包装普通函数与箭头函数时 `this` 的差别」说明）。

## 本批的自查

1. **parity 抓出源码块不同步 2 处**：例 4 表单一节改动后忘了同步 `data-lang="js"` 源码块；
   例 5 的 `.d-todo-del` 改名后预览与源码各剩一处 `.d-del`。两处都被
   `check-demo-parity.py` 精确定位（报出不一致的字符偏移），改完复验通过。
2. **修掉第一版留下的真 bug（CDP 实测抓出）**：委托演示里「新增条目」的按钮写成
   `className = 'd-del'`，而委托监听器找的是 `.d-todo-del`——于是新条目**删不掉**，
   与演示文案「它的删除按钮没绑任何监听器，照样能删」直接矛盾
   （实测：新增后 `querySelectorAll('.d-todo-del').length` 仍是 2）。
   改正类名后复验：新增的第三条能被委托监听器删除，日志给出
   `target = button，closest("li") 找到「测试任务」并删除；列表还剩 2 条`。
3. **删掉两处不诚实的演示写法**：
   - 例 2 原来用 `event.currentTarget === window` 判断箭头函数的 `this`——逻辑写反了
     （`currentTarget` 永远是元素，不可能等于 `window`）。现在直接打印
     `this === event.currentTarget`，让普通函数报真、箭头函数报假；
   - 例 5 的对照按钮原来声称「同一个按钮被绑了很多次、下次点击会多跑」——
     其实**同一个函数重复绑只生效一次**，与例 1 立下的规矩打架。现在如实说明
     「重复绑不会重复执行，真正的代价是每条新条目都得补绑、漏了就失灵」。
4. **例 3 的 document 监听器加了目标守卫**：原来它会记下页面上任何一次点击
   （包括点「开演」按钮那一下），对比列表里多出一行无关记录；
   现在只在 `event.target === 目标按钮` 时记录，输出干净。
5. 演示自己打印的数值不涉及过渡中间值（例 3 读的是事件顺序、例 6 读的是计数器），
   第三十七式刚立下的「演示要读的属性不加过渡」在本式不构成风险。
