**`site/basics/37-js-dom.html` DOM 操作**（5 个演示 + 3 道练功）：

- 「DOM 是什么」：节点树示意（document → html → head/body），一句话立住全章主线
  「改页面＝找到节点 → 改内容、属性、类名或位置」；
- **第一件事：找到元素**——五种查法对照表
  （<code>getElementById</code> 最快、<code>querySelector(All)</code> 最通用、
  <code>getElementsByClassName</code> 返回“活的” <code>HTMLCollection</code>、
  <code>closest</code> 往上找、<code>matches</code> 自问自答）
  + 例 1 九行实测：**静态快照与活集合的差别**（插入新项后
  <code>querySelectorAll</code> 仍是 2 条、<code>getElementsByClassName</code> 变 3 条）、
  <code>[...list]</code> 转数组后 <code>map</code>、框内查找 vs 全文档查找（3 条）；
- **第二件事：读与改内容、属性**——<code>textContent</code> / <code>innerHTML</code> /
  <code>getAttribute</code> 与 <code>dataset</code> 的区别 + 例 2 读改写实测，
  并演示「<code>value</code>（当前状态）≠ <code>getAttribute("value")</code>（初始值）」
  这一新手必踩的坑（读者改完输入框再点按钮即可看到两者分岔）；
- **第三件事：类名与样式**——<code>classList</code> 五连（add/remove/toggle/contains/replace）、
  <code>style.setProperty</code> 改 CSS 变量、<code>getComputedStyle</code> 只读最终样式
  + 例 3：切 <code>is-active</code> 类名（背景色真的变了）与
  <code>setProperty("--scale", 1.2)</code>（字号 14.4px → 17.28px）；
- **第四件事：增、删、换**——做法对照表（<code>append/prepend/before/after</code>、
  <code>replaceWith/remove</code>、<code>cloneNode(true)</code>、
  <code>insertAdjacentText</code>、<code>DocumentFragment</code>）+ 例 4 四个按钮
  （加/删/复制/批量插入 500 项计时）；
- **安全：<code>innerHTML</code> 是“代码执行入口”**——例 5 同一段字符串两种命运
  （<code>innerHTML</code> 解析出 2 个子元素；<code>textContent</code> 0 个子元素、原样显示），
  配「给动态内容的三个习惯」警示框；
- 表单控件读值速查表（文本/复选/单选/下拉/整表 <code>elements</code>），
  并预告 <code>new FormData(form)</code> + <code>Object.fromEntries</code> 这对组合（第四十式会用）；
- 本式小结六条 + 练功三题（留言板、给条目加删除按钮、思考两种“信任级别”）。

## 本批的自查

1. **把例 4 的计时改成真证据**：初版两种写法都只是 <code>append</code>，
   实测 0.6 ms vs 0.6 ms——浏览器把多次插入合并结算，读者看不到任何差别，
   而正文却写着“代价不一样”，属于**演示与结论不符**。
   现在第一种写法在循环里补一句 <code>list4.offsetHeight;</code>（逼浏览器立刻结算布局），
   实测 **90.5 ms vs 0.5 ms**，并同步把这个前提写进代码注释、
   结论行与「三个习惯」警示框（“别在循环里边写边读”），预览与源码块两处一起改。
2. **五个演示逐条做操作级断言**（<code>cdp-eval.js</code>）：
   例 1 九行文案、例 2 点击后读「当前值 vs 初始值」、例 3 点击后读
   <code>className</code> / <code>backgroundColor</code> / <code>--scale</code> / <code>fontSize</code>、
   例 4 四个按钮的操作序列与批量计数（<code>afterOps: 4</code>、<code>batchCount: 500</code>）、
   例 5 两个盒子的 <code>children.length</code>；http:// 与 file:// 各跑一遍。
3. **人工目检**：<code>cdp-shot.js</code> 截例 4 区块（含做法对照表、演示、源码块），
   版式与纸墨风无异常。
4. **例 3 的过渡色陷阱（本批新确立的约定）**：原来卡片除了
   `transition: transform .2s ease-out`，还给 <code>background</code> /
   <code>border-color</code> 也加了 <code>.2s</code> 过渡，
   点“切换 <code>is-active</code>”的瞬间 <code>getComputedStyle(card).backgroundColor</code>
   读到的是**过渡途中的旧色**，打印出的文案与“切换成功”自相矛盾。
   现在过渡只留给看得见的形变（<code>transition: transform .2s ease-out</code>），
   **演示自己要读出来打印的属性一律不加过渡**；
   该约定已写入 `conventions.md` §3.1 第 5 条与 `skills/build-demo/SKILL.md`。
