**`site/basics/40-js-storage.html` 浏览器与本地存储**（4 个演示 + 3 道练功 + 3 个结构块）：

- 「window：浏览器递给你的总管家」：说明它同时是全局对象（顶层 <code>var</code> 与
  <code>window.setTimeout</code> 的等价关系）+ 视口/滚动/像素比速查表 + 心法
  “先知道屋里有什么，遇事才不至于自己造轮子”；
  **例 1**：读一次窗口信息（视口、已滚动像素、屏幕像素比），另一个按钮让页面向下滚 300px，
  0.8 秒后如实报出“目标 300 / 实际 300”，并顺带演示了 <code>scroll</code> 事件的
  每 200ms 记一行的简单节流（回指第三十八式）；
- 「location 与它的邻居们」：window / document / location / history / navigator /
  localStorage 六行分工表 + hash 与 <code>hashchange</code> 的说明；
  **例 2**：读出 <code>href</code>、协议、主机、hash、浏览器语言与联网状态
  （file:// 下如实显示“本地文件没有主机”），两个按钮改 / 清 hash，
  <code>hashchange</code> 逐次记录（实测两次记录分别落到 <code>#dojo40</code> 与「（空）」）；
- 「本地仓库：localStorage 与 sessionStorage」：五种操作速查表
  （setItem / getItem / removeItem 与 clear / JSON.stringify 与 parse / sessionStorage）
  + 一句“只在这台电脑这个浏览器里、不会自动上传、别放敏感信息”；
  **例 3**：便签存进 <code>dojo40-notes</code>，刷新仍在；存前
  <code>JSON.stringify</code>、读时 <code>JSON.parse</code> 且用 try/catch 兜住坏数据；
  另监听 <code>storage</code> 事件，别的标签页改了这边跟着刷新；
- 「数据从哪来：file:// 的那道坎」：先给 <code>fetch</code> 的常规写法结构块，
  再用警示框讲清 file:// 下浏览器一律拦下 fetch / XHR 读本地文件，
  两条出路是“起本地服务器”或“把数据写成 JS 用 <code>&lt;script src&gt;</code> 引进来”；
  **例 4** 就演示后者：本页 <code>head</code> 真的挂了
  <code>&lt;script src="../data/demo-greeting.js"&gt;</code>，
  点按钮读出那份数据里的问候语；演示后紧跟两个结构块，把那一行与本页真正用到的
  <code>site/data/demo-greeting.js</code> 全文摆给读者；
- 本式小结六条（含“键名加项目前缀”）+ 练功三题（主题开关、hash 页内导航、
  思考 file:// 下 fetch 与 script 的差别对静态站带数据的启示）。

## 本批的自查

1. **例 4 的写法改过一轮**：初版把 <code>&lt;script src&gt;</code> 直接放进演示预览，
   源码块里就得写下 <code>&lt;\/script&gt;</code> 转义，导致
   `check-demo-parity.py` 报「HTML 不一致 + JS 多出一块」（预览侧的脚本节点与源码侧的
   script 节点对不上）。改为“页面 head 真加载 + 演示只负责读”之后 parity 一次通过，
   而且更贴近真实项目做法：数据在页面加载时就到位。
2. **四个演示逐条操作级断言**（http:// 与 file:// 各跑一遍）：
   - 例 1：读一次得「视口 1280 × 900，已向下滚 0 px」；点滚动后 1.2 秒读到
     「滚动中 …… 296 px」与「滚完之后（目标 300 px）…… 300 px」；
   - 例 2：改 hash 后 <code>location.hash === "#dojo40"</code>，
     清掉后为 <code>""</code>，两次 <code>hashchange</code> 都记进了列表；
   - 例 3：保存后 <code>localStorage.getItem("dojo40-notes")</code> 为
     <code>["第一条便签"]</code> 且列表同步；直接改存储再派发 <code>storage</code> 事件，
     列表跟着变成新内容（证明“重新读存储”这条路径可用）；清空后存储为 <code>null</code>、
     列表 0 条；
   - 例 4：读出「取经归来，仍是少年。」，file:// 下同样成功——这正是本式要讲的结论。

   单独重跑与随后连跑均复现不了——根因是先前那轮端口冲突留下的浏览器实例
   （见第 47 号归档），清理后串行重跑全部为“错误：无”。
   **再次印证：CDP 工具必须串行、残留进程必须清干净。**

   转义过的 <code>&lt;\/script&gt;</code> 在结构块里正确还原显示为
