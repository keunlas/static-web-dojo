## 本批完成的事

**`site/basics/23-css-responsive.html` 响应式心法**（5 个演示 + 3 道练功）：

- <code>viewport</code> 那一行的三个要点（少了它会变成 980px 缩放、
  <code>width=device-width</code> 才能让媒体查询有意义、**永远不要禁用缩放**）；
- 移动优先 vs 桌面优先对照表（默认写给窄屏，用 <code>min-width</code> 逐级增强）；
- 媒体查询语法三种写法（<code>min-width</code>、区间 <code>40em &lt;= width &lt; 64em</code>、
  以及 <code>and</code> / 逗号 / <code>not</code>）+ 条件表（方向、深浅色偏好、减少动效、
  指针粗细、悬停能力、打印）；
- 例 1 媒体查询现场：<code>min-width: 640px</code> 一切换两列，脚本实时报告“视口宽多少、
  命中哪个分支”（宽窄两种视口都已实测）；
- 断点怎么选：**按内容散架处选**，参考值 36/48/62/75em，并说明媒体查询里
  <code>em</code> 相对浏览器默认字号（用户调大字号时断点跟着变，<code>px</code> 不会）；
- 四件武器表：流式尺寸 → 弹性/网格 → 媒体查询 → 容器查询，原则是“能靠前解决就别用后面”；
- 例 2 流式字号（<code>clamp(1.25rem, 1rem + 2.4vw, 2.2rem)</code>），脚本报告当前字号与视口；
- 场景一：窄屏表格 → 可横向滚动外壳（<code>overflow-x: auto</code> + <code>min-width</code>）
  + 例 3（外壳限宽 26rem 以模拟手机，实测“内容 560px / 可见 414px，需要横向滚动”）；
  并补一条无障碍提醒：可滚动区域要加 <code>tabindex="0"</code> + <code>role="region"</code> + 说明；
- 场景二：次要内容的处理顺序 **重排 &gt; 折叠 &gt; 隐藏**（附三种写法的代码块）；
- 场景三：触控目标尺寸（WCAG 2.2 AA 最低 24×24，Apple HIG 44pt / Material 48dp 推荐）
  + 例 4 实测小链接 18px 与按钮式链接 44px；
- 容器查询：<code>container-type: inline-size</code> + <code>@container</code> 写法
  + 例 5（<code>resize: horizontal</code> 让读者直接拖右下角改变容器宽度，
  卡片在 420px 处从竖版切到横版）；
- 测试三步（拖窗口 / 换输入方式 / 上真机）与课外阅读（MDN 媒体查询、容器查询）。

## 本批的三处“实测校准”

1. **CSS 顺序坑（真实踩到并写进正文）**：例 1 初版把
   <code>.wide-only { display: none }</code> 写在媒体查询<strong>之后</strong>，
   同权重下后写的赢——宽屏永远显示不出那个标签（实测 <code>wideTag: "none"</code>）。
   把基础规则移到媒体查询之前后恢复正常，并把这个坑写成正文里的一段：
   “条件成立后，里面的规则依然要按层叠规则参与竞争”。
2. **演示要能“演出来”**：例 3 的表格在宽屏上根本不需要滚动（800px 容器放得下 560px 表格），
   于是给外壳加 <code>max-width: 26rem</code> 模拟手机宽度，复测“需要横向滚动”成立。
3. **数字要在样式就位后再量**：例 4 初版脚本在解析时量高度，报出 14px 的错数
   （正确值 18px），改为 <code>DOJO.ready</code> 后再量；同时把例 1、2、3 的实时数字
   都挂上 <code>resize</code> 监听，窗口一变数字跟着变。
