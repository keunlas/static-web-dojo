     “HTML 描述、CSS 声明、JS 下命令”的分工；
   - 三种引入方式表（外部脚本推荐 / 内部脚本 / 元素事件属性不要用）与

2. **工具修正（离线检查的误报，重要）**：
   - 现象：`check-offline.sh` 的“禁用技术扫描”用 grep 找 `type="module"|fetch(|XMLHttpRequest`，
     而第二十七式的**正文**里有一句解释“ES 模块（`type="module"`）内部自动严格”——
     说明文字被当成了违规，检查直接失败。
   - 判断：JS 篇必须讲 `fetch`、`XMLHttpRequest`、ES 模块以及它们在 file:// 下的限制，
     正文与教学源码块出现这些字眼是**应该的**；旧写法属于“检查过宽”。
   - 修复：新增 `tools/check-offline-tech.py`，做**脚本感知**的扫描——
     只检查页面里真实会执行的 `<script>`（跳过 `type="text/plain"` 的教学源码块），
     在脚本体内找 `fetch(` / `XMLHttpRequest`，在属性里找 `type="module"`；
     `check-offline.sh` 的第 2 步改为调用它，输出格式不变。
   - 文档同步：`conventions.md` §5 第 3 条补充口径说明；`architecture.md` 的 tools 一览更新。
